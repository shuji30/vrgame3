# アート・サウンド方針書(vrgame3)

2026-11-03 作成

この文書は、vrgame3 の見た目(スタイル・色・モデル・光・UI・演出)と音(環境音・効果音・BGM・振動)の方針と、マイルストーンごとにそろえる素材を決めるものである。ルール・モード・マイルストーンのゲート条件は企画書 `docs/plan.md` が正で、この文書は「見た目と音」だけを扱う。

- 数値はすべて**目安**であり、Pimax 8KX の実機で fps と見え方を確かめて調整する
- Unity エディタでの設定は Claude Code からはできないため、ユーザーが行う手順として書く

---

## 1. スタイルの方針

「明るいローポリ+柔らかい陰影」。陽ざしの強い南国を、角を落としたおもちゃのような形で表す。

| 項目 | 方針 |
| --- | --- |
| 色調 | 高明度・中彩度。真っ黒と純色(彩度100%)は使わない。影色は黒ではなく青紫寄りにする |
| 形 | ローポリだが角は面取りする(ベベル1〜2段)。直方体より樽型・丸太・角丸を好む |
| 陰影 | フラット寄りのシェーディング+焼き込みの柔らかい影。強いスペキュラーや金属感は出さない(Smoothness 0.1〜0.3 目安) |
| 質感 | テクスチャで模様を描き込まない。色の塗り分けと形で見せる。例外は手に持つ物とボールの柄 |
| キャラ | 丸みのあるデフォルメ人形風。頭身2〜2.5、手は丸い手袋状、指なし。目と口はテクスチャ差し替えで表情を出す |
| 舞台 | 空に浮かぶ小島。島の縁から下は雲海。建物は木と布(帆布・日よけ)が中心 |

参考作品に似せないためのルール:

- 参考作品のキャラ造形(球形の手足が浮く体型など)、ロゴ、UI レイアウト、効果音のフレーズを真似しない
- 人形は「木製の玩具」をモチーフにする(木目の色・ペイントの継ぎ目・ボタン目)。これを独自の軸にする
- 色の主役は海の青緑と夕焼けのコーラル。白+水色主体のスポーティな配色は避ける

## 2. カラーパレット

### 2.1 共有パレットの作り方

全モデルで1枚のパレットテクスチャ(グラデーション画像)を共有し、マテリアルを1つにまとめてドローコールを減らす。

| 項目 | 仕様(目安) |
| --- | --- |
| ファイル | `Assets/_Project/Art/Palette/T_Palette.png` |
| サイズ | 256×256 px、8列×8行のセル(1セル32px) |
| 並び | 列=色の系統(海・砂・植物・木材など)、行=上が明るく下が暗い8段階のグラデーション |
| 取り込み設定 | Filter Mode: Point / Generate Mip Maps: オフ / Compression: None / sRGB: オン / Wrap: Clamp |
| マテリアル | `Assets/_Project/Art/Materials/M_Palette.mat`(URP/Simple Lit か URP/Lit、Smoothness 0.2 目安) |
| UV の置き方 | モデルの各面の UV をセルの中央付近に小さく縮めて置く(セル境界から 4px 以上離す) |

### 2.2 運用ルール

- パレットの色を変えるときは、セルの位置を動かさず色だけを変える(全モデルに一斉に反映される)
- セルを足すときは空きセルを使い、既存セルの意味を変えない。変更は下の表に記録する
- パレット以外のテクスチャを使ってよいのは、手に持つ物の柄・人形の顔・UI・水面・空だけ
- 発光させたい物(ピンの光、的の中心)は同じパレットを使う発光用マテリアル `M_PaletteEmissive` を1つだけ用意する

### 2.3 色の候補と役割

| 列 | 系統 | 主に使う物 | 基準色(明→暗の代表) |
| --- | --- | --- | --- |
| 0 | 海・水 | 海面、プール、浅瀬 | `#7FE3D6` / `#2FB5B0` / `#1A7A8C` |
| 1 | 空・遠景 | 空、遠くの島、雲海の影 | `#CFF1FF` / `#8FD3F4` / `#6C8FCF` |
| 2 | 砂・地面 | 砂浜、小道、レーンの床 | `#FFF1CF` / `#F2D49B` / `#C9A26B` |
| 3 | 植物 | ヤシの葉、草、低木 | `#B9E27A` / `#6CC36A` / `#2F8A5B` |
| 4 | 木材 | 小屋、ピン置き場、弓、人形の体 | `#F0C995` / `#C98B55` / `#8A5A3B` |
| 5 | 布・アクセント暖色 | 日よけ、旗、夕焼け | `#FFB4A2` / `#FF7F6B` / `#E0525E` |
| 6 | UI のアクセント | スコア強調、選択中、ゴール | `#FFD24A`(黄)/ `#FF8A3D`(橙)/ `#3AA7FF`(青) |
| 7 | 無彩色・影 | 岩、白いピン、文字、影色 | `#FFFDF7` / `#B8B4C8` / `#4A4660` |

- 最も暗い色でも `#2A2640` 程度にとどめ、純黒 `#000000` は使わない
- UI の文字色は `#FFFDF7`(背景が明るいとき)か `#3A3550`(背景が暗いとき)の2色に絞る

## 3. 描画負荷の予算(Pimax 8KX)

8KX は片目あたりの描画解像度が非常に高く、ピクセル数の負荷が支配的になる。**60fps(1フレーム約16.7ms)を目標**とし、以下はすべて目安とする。企画書のゲートもすべて 60fps を基準にしている。予算は 75fps 想定で組んだ値のまま残し、余裕分として使う。

### 3.1 ポリゴンとテクスチャ

| 区分 | 例 | 三角形数(目安) | テクスチャ(目安) |
| --- | --- | --- | --- |
| 手に持つ物 | ボール、弓、矢、ラケット | 1,500〜5,000 / 個 | パレット+柄用 512〜1024px 1枚まで |
| 人形(CPU・観客) | デフォルメ人形 | 1,500〜3,000 / 体 | パレット+顔 256px |
| 会場の大物 | レーン、小屋、卓球台、的 | 2,000〜15,000 / 個 | パレットのみ |
| 小物 | ピン、ベンチ、看板 | 300〜1,500 / 個 | パレットのみ |
| 中景 | ヤシの木、岩 | 300〜1,000 / 個(LOD1 で半分) | パレットのみ |
| 遠景 | 遠くの島、雲海 | 板ポリかごく粗いメッシュ、合計 2,000 程度 | パレットかスカイボックスに描き込み |
| 画面全体 | 視界に入る合計 | 30万〜50万(両目分ではなく1視点分) | — |

### 3.2 マテリアル・ドローコール

| 項目 | 目安 |
| --- | --- |
| 1シーンのマテリアル数 | 10 個以下(パレット、パレット発光、水、空、柄物2〜3、UI、パーティクル) |
| SetPass / バッチ | 200 以下(Frame Debugger / Stats で確認) |
| 動かない物 | Static にして静的バッチングかライトマップ対象にする |

### 3.3 ライトと影

- 太陽の Directional Light 1灯だけ。Mode は Mixed、Lighting Mode は Baked Indirect か Shadowmask
- 会場や地形の影はライトマップに焼き込む。リアルタイム影はボール・ピン・人形など動く物だけ
- 追加ライト(Point/Spot)はリアルタイムでは使わない。必要なら Baked にする
- 動く物の明るさはライトプローブ、映り込みは焼き込みのリフレクションプローブ1個(128px 目安)

### 3.4 ポストエフェクト

- 既定は**すべてオフ**。色はパレットとライトで作る
- Motion Blur・Vignette・Depth of Field・Chromatic Aberration・Lens Flare・Film Grain は使わない(酔いと負荷)
- Tonemapping と Bloom は M4 で fps に余裕があれば検討する。Bloom を使う場合も High Quality Filtering はオフ

### 3.5 透過・パーティクル

- 半透明(Alpha Blend)は重なると 8KX で急に重くなる。葉や紙吹雪は Alpha Clip(不透明扱い)にする
- 半透明を使ってよいのは水面と UI の背景板だけ。顔の近くに大きな半透明を置かない
- パーティクルは同時 300 個以下、Unlit、テクスチャは 64〜128px。ソフトパーティクルは使わない

### 3.6 URP の設定手順(ユーザーが Inspector で行う)

現状は `Assets/Settings/PC_RPAsset.asset` と `PC_Renderer.asset`(Forward+)、OpenXR は Single Pass Instanced になっている。`SampleSceneProfile` には Bloom・Vignette・Tonemapping・Motion Blur が入っている。

1. Project Settings → Quality で、PC 用の品質レベルの Render Pipeline Asset が `PC_RPAsset` になっているか確認する(`Mobile_RPAsset` は使わない)
2. `PC_RPAsset` を選び、Inspector で次を設定する
   - Rendering: Depth Texture オフ / Opaque Texture オフ(今はどちらもオン。使う効果が出たら戻す)
   - Quality: HDR オフ(Bloom を入れるまで)/ Anti Aliasing (MSAA) 4x(今はオフ。負荷が重ければ 2x)/ Render Scale 1.0
   - Lighting: Main Light は Per Pixel、Cast Shadows オン / Additional Lights はオフか Per Vertex、Additional Lights の Cast Shadows オフ
   - Shadows: Max Distance 20(今は 50)/ Cascade Count 1〜2 / Shadow Resolution 1024〜2048 / Soft Shadows オフか Low
3. `PC_Renderer` の Rendering Path は Forward+ のままでよい(GPU Resident Drawer を使うため)。SRP Batcher がオンか確認する
4. シーンのカメラ(XR Origin の Main Camera)で Post Processing のチェックを外す。Volume を置く場合も Motion Blur と Vignette は必ず外す
5. Project Settings → XR Plug-in Management → OpenXR で Render Mode が Single Pass Instanced のままか確認する
6. 解像度の調整は Unity の Render Scale より先に、Pimax 側のアプリ(Pimax Play / PiTool)のレンダー品質と視野角設定で行う。Parallel Projections はゲームが正しく映るならオフにする(オンは負荷が増える)
7. 毎回の確認:実機で OpenXR の fps 表示(SteamVR のフレームタイミング)を見て、16.7ms を超える場面を記録する

## 4. 3Dモデルの調達

### 4.1 調達先とライセンス(目安)

ライセンスは変わることがあるので、**ダウンロードの都度、配布ページとアーカイブ内の LICENSE を確認する**。

| 入手先 | 主な用途 | ライセンス(目安) | 表記 |
| --- | --- | --- | --- |
| Kenney(kenney.nl) | ボール、ピン、小屋、小物 | CC0 | 不要(記録はする) |
| Quaternius(quaternius.com) | ヤシの木、岩、人形の素体 | CC0 | 不要(記録はする) |
| Poly Haven(polyhaven.com) | 地面・木目テクスチャ、HDRI(反射用) | CC0 | 不要(記録はする) |
| Poly Pizza(poly.pizza) | 足りない小物 | CC0 / CC-BY 混在 | CC-BY なら必要 |
| Unity Asset Store(無料) | 水面シェーダー、パーティクル | Asset Store 標準ライセンス | 規約に従う |
| Sketchfab | 目立たせたい1点物 | モデルごと(CC-BY が多い) | 多くは必要 |
| フォント:Google Fonts など | UI 文字 | SIL OFL が多い | ライセンス文を同梱 |

- 優先順は CC0 → CC-BY → その他。CC-BY-NC・CC-BY-ND・「Editorial」は使わない(改変や利用条件で困るため)
- 参考作品のファンメイドモデルは使わない

### 4.2 取り込み時のルール

| 項目 | ルール |
| --- | --- |
| 置き場 | `Assets/ThirdParty/<提供元>/<パック名>/` にパックのフォルダ構成のまま置き、LICENSE も一緒に入れる。中身には手を加えない |
| スケール | 1 unit = 1 m。ボウリングのボールは直径約 0.22m、ピンは高さ約 0.38m を目安に、取り込み直後に Cube(1m)と並べて確かめる |
| 使い方 | ThirdParty のモデルを直接シーンに置かず、`_Project/<領域>/Prefabs/` にプレハブ(またはプレハブ バリアント)を作り、そこでスケール・コライダー・マテリアルを設定する |
| 向き | 前が +Z、上が +Y。ずれていればプレハブの子にして回転で吸収する |
| 改変 | メッシュの形や UV を直す必要があるときは、Blender で編集したものを `Assets/_Project/Art/Models/` に別名(例:`SM_PalmTree_A_mod.fbx`)で書き出す。原本は ThirdParty に残す |
| 命名 | メッシュ `SM_`、スキン付き `SK_`、テクスチャ `T_`、マテリアル `M_`、プレハブ `P_` |

### 4.3 パレットへの差し替え方

| 元の作り | 差し替え方 |
| --- | --- |
| 1色ごとに別マテリアル(Quaternius に多い) | 改変版を作り、UV をパレットの該当セルに寄せて1マテリアルにまとめる。数が少なければ当面は色だけパレットに合わせたマテリアルで代用してよい |
| 独自のカラーマップ画像を UV で参照(Kenney の一部) | まずはそのまま使い、色味が浮くときだけ改変版で UV をパレットへ付け替える |
| 頂点カラー | 改変版で頂点カラーを UV に焼き替えるか、頂点カラー対応シェーダーを1つだけ用意する |
| テクスチャ前提のリアル寄りモデル | 原則使わない |

### 4.4 クレジットの記録

- 取り込んだ時点で、第10章の記録表に1行追加する(CC0 も含めて全部)
- パックの LICENSE ファイルは削除しない
- 表記が必要な素材を使ったら、M4 でゲーム内のクレジット画面にも載せる

## 5. ライティングと時間帯

### 5.1 基本の作り方

- 環境光は Skybox から(Environment Lighting Source: Skybox)。焼き込みは Progressive GPU Lightmapper
- ライトマップ解像度は 10〜20 texel/m を目安。手前の会場は高め、遠景はライトマップ対象外(Unlit か頂点色)
- スカイボックスは HDRI ではなく、3色グラデーション(天頂・地平・地面)の軽いスカイボックスマテリアルにする。スタイルに合わせやすく軽い
- 霧(Fog)は Linear で遠景の島を空色に溶かす。距離感が出て遠景を粗くできる

### 5.2 朝・昼・夕焼けの3パターン(M1 では作らない)

| 時間帯 | 太陽の角度(目安) | 太陽の色 | 空(天頂 / 地平) | 影の色 | 霧 |
| --- | --- | --- | --- | --- | --- |
| 朝 | 仰角 20°、東 | `#FFE2B8` | `#9FD8F2` / `#FFE9CC` | `#8FA8D8` | 少し濃い |
| 昼 | 仰角 60° | `#FFF8EA` | `#5FC3F0` / `#D8F4FF` | `#7B8FD0` | 薄い |
| 夕焼け | 仰角 10°、西 | `#FF9E6B` | `#6C7FD0` / `#FFB089` | `#7A5C9E` | 暖色で中程度 |

作り方:

1. 会場のメッシュは1つのシーンにまとめ、時間帯ごとにライトの向き・色・スカイボックス・霧だけを変えて焼く
2. 焼いたライトマップ一式を時間帯ごとに保存し、種目に入るとき(ロード時)に切り替える。切り替えは小さなスクリプトで、`LightmapSettings.lightmaps`・スカイボックス・霧・太陽の色をまとめて差し替える。ライトプローブとリフレクションプローブも同時に差し替える
3. Unity 6 の Adaptive Probe Volumes の Lighting Scenarios も候補だが、ライトマップ併用時の扱いを確かめてから決める

VR で避けること:

- プレイ中に時間帯を連続で変化させない(視界全体の明るさが動くと不快)。変えるのはロード時だけ
- 太陽をプレイヤーの正面(レーンの奥など)に置かない。逆光で的やピンが見えにくくなる。夕焼けでも太陽は横か背中側に置く
- レンズフレア、ゴッドレイ、強い Bloom を入れない
- 暗すぎる場面を作らない(夕焼けでもピンと UI ははっきり見える明るさにする)

## 6. UI・文字

### 6.1 文字の大きさと距離(目安)

文字の高さは「距離 × 0.03」(視角およそ 1.7°)以上を目安にする。8KX はレンズの周辺がぼやけるので、大事な文字は視線の正面 ±30° 以内に置く。

| 用途 | 置く距離 | 文字の高さ(目安) |
| --- | --- | --- |
| 手元の説明・設定 | 0.8〜1.2 m | 2.5〜4 cm |
| スコア(手元の小型板) | 1.5〜2 m | 5〜7 cm |
| スコア(レーン奥の大型板) | 4〜6 m | 15〜20 cm |
| ストライク等の大きな文字 | 6〜18 m(ピン付近) | 50 cm 以上 |

- 文字は TextMeshPro(SDF)で描く。フォントは丸みのある日本語フォント(例:M PLUS Rounded 1c、Noto Sans JP など SIL OFL のもの)を1〜2種に絞る
- 文字には縁取り(Outline 0.15〜0.2)か不透明の背景板を付け、景色の上でも読めるようにする
- UI は Screen Space ではなく World Space の Canvas に置く。顔に貼り付けて追従させない(必要なら遅れて付いてくる方式にする)
- 0.5 m より近くに文字を出さない(目の焦点が合いにくい)

### 6.2 スコア表示の置き方(ボウリング)

- 大型スコア板:レーン奥の上部、目の高さより少し上(仰角 10〜15°)。10フレームの表をここに出す
- 小型スコア板:ボール置き場の横、腰〜胸の高さ。現在フレームと合計だけ出す
- スコア板は景色の一部(木の看板・黒板風)としてデザインし、浮いた UI パネルにしない

### 6.3 色だけに頼らない

- ストライクは「X」、スペアは「/」、ガターは「-」の記号で表す(色は補助)
- 選択中のボタンは色に加えて、枠の太さ・少し前に出る・アイコンの変化で示す
- 赤と緑の対比で意味を伝えない(成功/失敗は記号と文字と音で伝える)
- ランク(ブロンズ〜プラチナ)は色に加えて、メダルの形か星の数を変える

## 7. エフェクト・演出

### 7.1 原則

- **カメラは一切動かさない**(揺らす・ズーム・スローで視点を寄せる、すべて禁止)
- **点滅は 1秒に3回未満**、視界全体が白くなるフラッシュや明るさの急変はしない
- 演出は「プレイヤーから離れた場所」で起こす。顔の前を紙吹雪や光で覆わない
- 盛り上げは「目に入る光と動き」+「音」+「振動」の3つを重ねて作る

### 7.2 ボウリングの演出案

| 場面 | 見た目 | 音 | 振動 |
| --- | --- | --- | --- |
| 投げた直後 | なし(ボールに集中させる) | 転がる音 | 離した瞬間に短く1回 |
| ストライク | ピン置き場から紙吹雪(Alpha Clip、200個程度、2秒)/ 倒れたピンが順に光る(発光マテリアルを0.5秒で上げて1秒で戻す)/ レーン脇のライトが奥から手前へ1回流れる / 大型スコア板に「STRIKE!」 | ストライクのジングル+人形たちの歓声 | 両手に中くらいの長め1回(握っていなくても祝福として) |
| スペア | 紙吹雪は少なめ・色違い / スコア板に「SPARE」 | 短いジングル | 軽く1回 |
| ガター | 小さな「ぷしゅっ」とした煙(遠くで) | 残念そうな短い音(嫌みのない音) | なし |
| 10フレーム終了 | スコア板の合計が数字を回すように確定 / 小さな花火を遠くの空に(島の外) | 拍手 | なし |

- 光の変化はなめらかに上げ下げし、オンとオフの切り替えにしない
- 紙吹雪の発生位置はプレイヤーから 10m 以上離す

## 8. サウンド

### 8.1 環境音

| 音 | 置き方 | 備考 |
| --- | --- | --- |
| 波 | 島の縁(海側)に 3D の音源を2〜3個、ループ | 位置で海の方向が分かるようにする |
| 鳥 | プレイヤーの周り 10〜20m の木の位置で、ランダム間隔(8〜20秒)の単発 | 同じ鳴き声が続かないよう 4〜6種を順番に |
| 風 | 2D(定位なし)の弱いループ | ヤシの葉の揺れる音を混ぜてもよい |
| 会場の生活音 | ボウリング小屋のきしみ・遠くの人の声(M2 以降) | 鳴らしすぎない |

### 8.2 効果音

| 種目 | 音 | 作り方の要点 |
| --- | --- | --- |
| 共通 | 掴む / 離す | 短く柔らかい音(布・木の手触り)。振動と同じタイミング |
| ボウリング | 投げる(風切り) | 手の速度が速いときだけ鳴らす |
| | 転がる | ループ音の音量とピッチをボールの速度に合わせる。床に落ちた瞬間の「ドン」を別に |
| | ピンが倒れる | ピン同士・ピンと床で2系統、各4〜6種をランダム+ピッチ ±5%。同時発音は 8 まで、同じピンは 0.03秒あける |
| | ストライク / スペア | 1〜2秒の短いジングル。ストライクは最も大きく明るく |
| | ボールの戻り | ボールリターンのゴロゴロ音 |
| アーチェリー | 弦を引く(きしみ)/ 放つ / 矢の風切り / 的に刺さる / 中心に当たる | 中心は特別な音を重ねる |
| 卓球 | ラケットに当たる / 台に弾む / 床に落ちる | 当たる音は強さで3段階に分ける |
| UI | 選ぶ / 決める / 戻る | 小さめ、木琴やマリンバ系で島の雰囲気に合わせる |

### 8.3 BGM の方針

- 種目のプレイ中は BGM なし(既定)。環境音とボールの音が主役で、音で上達が分かるようにする
- ハブ(島の広場)とリザルトだけ、明るく静かな曲(ウクレレ・スチールパン・マリンバ系)を小さく流す
- BGM は M2(ハブ)から。M1 では入れない
- 参考作品の曲調やフレーズに寄せない

### 8.4 空間音響(3D サウンド)

- 効果音(ボール・ピン・矢・ラケット)と波・鳥は 3D(Spatial Blend 1.0)、風・BGM・UI は 2D(0.0)
- 3D の音源はモノラル素材を使う。距離減衰は Logarithmic、Min Distance 1m・Max Distance 30m を目安(ピンは 18m 先なので届くように調整)
- 最初は Unity 標準の空間化で作る。方向感が足りなければ M4 で Steam Audio などの空間化プラグインを検討する(導入前にライセンスを確認)
- 音源の位置は物体に付ける(ピンの音はピンから、ジングルはスコア板から)

### 8.5 音量バランス(目安)

AudioMixer に Master / BGM / Ambient / SFX / UI のグループを作り、将来設定画面から変えられるようにする。

| グループ | 基準の音量(目安、Master 0dB に対して) |
| --- | --- |
| ストライクのジングル | -6 dB |
| ピンが倒れる | -8 dB |
| 転がる・矢・ラケット | -12 dB |
| 掴む・離す | -16 dB |
| UI | -16 dB |
| 環境音(合計) | -20 dB |
| BGM | -22 dB |

- 素材は取り込む前にラウドネスをそろえる(-16 LUFS 前後を目安に揃えてから Mixer で下げる)
- 実機のヘッドホンで、最大の音(ストライク)が耳に痛くないことを確認する

### 8.6 取り込み設定(目安)

| 種類 | 形式 | Load Type |
| --- | --- | --- |
| 短い効果音 | WAV 48kHz 16bit、モノラル | Decompress On Load |
| 環境音のループ | WAV / OGG、3D はモノラル・2D はステレオ | Compressed In Memory |
| BGM | OGG、ステレオ | Streaming |

### 8.8 触覚(コントローラー振動)との組み合わせ

Vive ワンドの振動は強弱と長さしか変えられない。音と同時に鳴らし、手で触れている物の出来事だけに使う(ストライクの祝福は例外)。強さと長さは `[SerializeField]` にしてユーザーが調整できるようにする。

| 出来事 | 強さ(0〜1、目安) | 長さ(目安) |
| --- | --- | --- |
| 掴む | 0.3 | 0.03 秒 |
| 離す・投げる | 0.4 | 0.04 秒 |
| ストライク(祝福) | 0.5 | 0.25 秒 |
| 弦を引いている間 | 0.1〜0.4(引いた距離に比例) | 連続 |
| 矢を放つ | 0.8 | 0.06 秒 |
| ラケットに当たる | 0.3〜0.9(ボールの速さに比例) | 0.04 秒 |

## 9. マイルストーン別のアート・音の作業一覧

最終的な割り当てとゲートは企画書が決める。ここではアートと音の側でそろえる物を並べる。

### M0

- 3.6 の URP 設定を適用し、実機で空のシーンの fps を測る(基準値として記録)
- 共有パレット v0(色は仮でよい)と `M_Palette` を作る
- 掴んで投げる確認用の仮ボール(パレット色の球)と、1m の基準キューブ
- 掴む・離すの振動(仮の値)。音はなくてもよい
- 頭と手の仮表示:手はコントローラー形の仮モデル(パレット色)、頭は他人から見えないので表示しない
- 第10章の記録表を用意する

### M1

ボウリングの「1レーンで10フレーム遊べる」に必要な物だけにする。

- 会場:海辺のボウリング小屋1棟、1レーン(レーン・ガター・ピン置き場・ボールリターン)、周りの砂浜とヤシの木数本、遠景は空と海と雲海だけ
- ライティング:昼の1パターンだけ焼き込む(朝・夕焼けは入れない)
- ボール:2〜3色(重さ違いが必要なら色で区別)、ピン10本(1種のメッシュ)
- スコア表示:大型スコア板と小型スコア板(6.2)、記号 X / - の表示
- 演出:ストライクとスペア(7.2 の表)、ガターの小さな演出
- 効果音:掴む・離す・転がる・ピン(2系統)・ストライク・スペア・ボールの戻り
- 環境音:波・鳥・風
- 振動:掴む・離す・ストライク
- 安全の案内(ストラップ・周囲確認)の看板の見た目(文字は 6.1 の大きさ)
- 身長・利き手の設定パネルの見た目(6.1 の大きさ、ボタンは大きめ)
- 入れないもの:人形(CPU・観客)、BGM、時間帯の切り替え、ハブ、ボールの柄の報酬

### M2

- 島のハブ(広場)と、ハブから会場への道、種目選択の看板
- 森の中のアーチェリー場(弓・矢・的、的の得点表示)
- アーチェリーの効果音と振動(8.2・8.8)
- ランク(ブロンズ〜プラチナ)のメダルの見た目、スコア保存の結果画面
- ハブの BGM 1曲
- 時間帯は M1 と同じ昼の1パターンのまま(3パターンは M4)
- 設定画面(連続移動のオン・オフ、休憩案内のオン・オフ)と、休憩案内の表示の見た目
- 2種目通しの fps 確認に合わせて、予算(第3章)を見直す

### M3

- ヤシの木陰の卓球台と、ラケット(手に持つ物として予算を多く割く)
- 卓球の効果音(強さ3段階)と振動
- CPU の人形(デフォルメ人形・木の玩具モチーフ)1体と表情テクスチャ数種、強さ3段階の見分け(帽子や色+記号)
- 観客の人形は少数(負荷を見て)
- 交代プレイの名前・順番の表示と、チャレンジの課題・結果表示の見た目

### M4

- 時間帯3パターン(朝・夕焼けの焼き込みを追加。5.2)
- 見た目の磨き込み:パレットの色調整、LOD、ライトマップの品質
- 報酬の見た目(ボールの柄、弓の色、帽子)
- BGM の追加、空間化プラグインの検討、音量設定画面のつまみ
- チュートリアル用の看板・矢印
- 表記が必要な素材のクレジット画面
