# VRスポーツリゾート 企画書(vrgame3)

2026-10-15 作成 / 2026-11-03 更新(M2 の具体化)

## 企画概要

南国の島リゾートを舞台に、手や体を実際に動かして遊ぶ「体感スポーツ集」をVRで作る。最初はボウリング1種目を完成させ、種目を1つずつ足していく。

| 項目 | 内容 |
| --- | --- |
| タイトル案(仮) | 未定(候補は下記) |
| ジャンル | VRスポーツ・ミニゲーム集 |
| 一言で言うと | 島のリゾートで、気軽に何度でも遊べるスポーツをVRで「本当に体を動かして」楽しむ |
| 1プレイ時間 | 1種目 3〜10分 |
| 体験の核 | 投げる・打つ・引くが自分の手の動きそのままに反映される気持ちよさ |

参考作品(Switch Sports / Wii Sports Resort 系)から借りるのは「誰でもすぐ遊べる操作」「短時間で終わる種目」「リゾートの明るい雰囲気」の3点に限る。キャラクター・名称・デザインは完全オリジナルにする。

差別化はVRならではの3点に置く。

- 手の位置と向きが1対1で反映されるため、フォームの上達がそのまま上手さになる
- 島の景色に囲まれる没入感(海、ヤシの木、夕焼けの時間帯変化)
- 種目間を島の中で歩いて移動する「ハブ空間」で、ゲーム集でも一つの場所にいる感覚を出す

### タイトル候補

| 候補 | 意味・由来 | 印象 |
| --- | --- | --- |
| ソラシマ・スポーツリゾート | 空に浮かぶ島(空島)のリゾート | 舞台がそのまま伝わる |
| アイランド・アクティブ | 島で体を動かす | 短く覚えやすい |
| ココナッツ・リーグ | 南国の果物とリーグ戦 | かわいく親しみやすい |
| サンセット・スポーツ | 夕焼けの島で遊ぶ | 雰囲気重視、落ち着いた印象 |
| ハレバレ・アイランド | 晴れ晴れとした島 | 明るく、日本語の響きが楽しい |
| ナミノリ・スポーツ | 海辺で波に乗るような爽快さ | 海の印象が強い |

「スポーツリゾート」は参考作品の名前に近いが、個人で遊ぶ範囲なら問題はない。

## ターゲットとプラットフォーム

対象は PC VR の Pimax 8KX(および他のPimaxシリーズ)で、自分で遊ぶための個人制作とする。ストア公開はしないので、審査や他機種への対応は考えなくてよい。

| 項目 | 方針 |
| --- | --- |
| 想定プレイヤー | 自分(家族や友人が試すこともある) |
| 対応デバイス | Pimax 8KX / Pimaxシリーズ(SteamVR経由) |
| 実行環境 | Windows PC(自宅PCは RTX 4070 Ti) |
| プレイ姿勢 | 立ってその場で遊ぶ。座りプレイも可能な種目を用意 |
| 必要スペース | 2m × 2m 程度、ベースステーションの検知範囲内 |
| 入力 | HTC Vive コントローラー(OpenXR の HTC Vive Controller Profile) |
| 目標フレームレート | 60fps 以上。ヘッドセットのリフレッシュレートも、設定できるなら 60Hz に合わせる(実機で要確認)。8KXは解像度が非常に高いため、描画負荷を抑えることを最優先にする |

## 種目ラインナップ

最初に作るのはボウリング、次にアーチェリー、卓球の順とする。「その場から動かない」「物理が単純」な種目ほど、個人開発でも完成度を上げやすく、VR酔いも起きにくい。

| 優先 | 種目 | VRとの相性 | プレイヤー移動 | 物理の難しさ | 一言メモ |
| --- | --- | --- | --- | --- | --- |
| 1 | ボウリング | 高 | なし | 低 | 投げる動作が直感的。MVPに最適 |
| 2 | アーチェリー | 高 | なし | 低 | 弦を引く手応えがVR向き。的当てで得点が明快 |
| 3 | 卓球 | 非常に高 | なし | 高 | 一番VRらしいが、高速ボールの当たり判定が難所 |
| 4 | パターゴルフ | 高 | 少し(ワープ) | 中 | 座ってもできる。コース作りが楽しい |
| 5 | フリスビー | 中 | なし | 中 | 投げて犬がキャッチ。島の雰囲気づくりに合う |
| 6 | 剣のチャンバラ | 中 | なし | 中 | 対CPU戦。手応え(当たったときの反発)の表現が課題 |
| 7 | テニス | 中 | 自動移動 | 高 | 自分で走れないため自動移動が必要。後回し |
| 8 | カヌー | 低 | 常に移動 | 中 | 景色は良いがVR酔いしやすい。オプション扱い |

種目数は3つそろった時点で「ゲーム集」として成立させ、4つ目以降は反応を見て決める。

## コアゲームプレイと操作設計

全種目で「トリガーを引いている間だけ掴み、離して投げる/放つ」を共通操作にし、説明なしで遊べるようにする。投げる速さと向きは、手を離した瞬間のコントローラーの速度から計算する。

### ボウリング(MVP)

1. ボール置き場でトリガーを引いてボールを掴む
2. レーンに向かって腕を振り、トリガーを離して投げる
3. 離した瞬間の手の速度でボールの速さ、手首のひねりで回転(カーブ)が決まる
4. 10フレームでスコアを競う。ストライク・スペアの演出で気持ちよさを出す

調整ポイントは次の3つ。

- 投げる力の補正:実際の腕振りは小さいので、速度に倍率をかけて「強く投げた感」を出す
- 床への投げつけ防止:手が床より下に行ってもボールは床の上から出る
- 投げ損ね救済:ファウルラインより手前に落ちたら自動で転がす

### アーチェリー

片手で弓を持ち、もう片方の手で弦を掴んで引き、離して矢を放つ。引いた距離で矢の速さが決まり、重力で山なりに飛ぶ。弦を引いている間はコントローラーを細かく振動させて手応えを出す(強さは `docs/art-direction.md` 8.8)。M2 で入れる。

操作(Vive ワンド。割り当ては共通のまま、グリップは使わない):

| 手 | 操作 |
| --- | --- |
| 弓を持つ手(利き手でない方) | 「はじめる」を押すと弓がこの手に付く。トリガーを引き続けなくてよい(持ち疲れ防止)。ゲームが終わるかハブへ戻ると外れる |
| 矢を引く手(利き手) | 手を弦の中央(矢をつがえる点)から 0.12m 以内に近づけてトリガーを引くと、矢が現れて弦を掴む。矢筒から取る動作はない |
| 引く | トリガーを引いたまま手を後ろへ引く。引いた距離は弦の中央からの距離で測り、最大 0.6m で止める |
| 放つ | トリガーを離す。引いた距離が 0.1m 未満なら矢は消え、本数を減らさない(空撃ち扱い) |

- 利き手は共通の設定を使い、左利きなら左右を入れ替える
- 矢の速さは、引いた距離 0.1〜0.6m を 15〜45m/秒に比例させる。重力は標準(9.81)
- 矢は飛んでいる向きに先を向け、前のフレームの位置からのレイで当たりを取る(高速ですり抜けないため)
- 刺さった矢はラウンドの終わりまで残し、次のラウンドの始めに消す。的の外へ飛んだ矢は 5秒で消す
- 射つ位置は射線の後ろ 1.5m × 1.5m に限る(TeleportArea で囲う)

ルール:

| 項目 | 内容 |
| --- | --- |
| 1ゲーム | 3ラウンド × 6本 = 18本。時間制限なし。1ゲーム 4〜6分の目安 |
| 的までの距離 | 1ラウンド目 10m、2ラウンド目 20m、3ラウンド目 30m。的は1つで、ラウンドの始めに次の距離へ置き直す(プレイヤーは動かない) |
| 的 | 直径 1.2m、10個のリング(1リング幅 6cm)。中心の高さは身長設定 × 0.85(170cm で約 1.45m) |
| 点数 | 中心から 10・9・…・1 点、的の外・地面は 0 点。線に掛かったら高い方。満点 180 |
| 中心(X) | 10点リングの内側半分(直径 6cm)は「X」として記録し、特別な演出と音を出す(点は10のまま。演出と音は `docs/art-direction.md`) |
| 表示 | 射つ位置の横の小型スコア板に、ラウンドごとの6本の点・ラウンド合計・総合計・残り本数。当たった矢の点は的の横にも数秒出す |
| 終わり方 | 18本目が刺さる(または消える)と結果を出す:総合計、ベスト(更新なら印)、腕前ポイントの増減とランク。結果の下に「もういちど」「ハブへ」 |

狙いやすさの補助(初心者向け):

- 「ねらいの補助」をアーチェリーの「はじめに」パネルでオン/オフでき、既定はオン。値は保存する
- オンのとき、弦を引いている間だけ、矢の飛ぶ道筋の最初の 4m を点線で出す(長さは Inspector で調整)。的に届くところまでは出さず、向きと山なりの具合だけ分かるようにする
- 補助のオン/オフでスコアとポイントの扱いは変えない(個人で遊ぶため)

調整できるようにする値(Inspector):つがえる距離、最大の引き、矢の速さの下限・上限、重力の倍率、的の距離3つ、的の直径、補助線の長さ、振動の強さ。

### 卓球

ラケットは手に持ったまま固定し、ボールとの当たり判定はラケットの速度と向きで反射を計算する。物理エンジン任せにすると高速ボールがすり抜けるため、専用の衝突計算(連続衝突判定)を自作する前提で、最も工数を見ておく。

### コントローラー

操作は HTC Vive コントローラー(Vive ワンド)に統一し、ハンドトラッキングは使わない。ボタンの割り当ては全種目で共通にする。

| 操作 | 割り当て |
| --- | --- |
| 掴む・離す | トリガー(引いている間だけ掴む) |
| テレポート | トラックパッドの中央を押し込み。押している間に放物線を表示し、離した地点へ移動 |
| スナップターン | トラックパッドの左右を押し込み |
| 連続移動(オプション) | 設定でオンにしたときだけ、テレポートの代わりにトラックパッドに触れた方向へ移動 |
| メニュー(M2) | メニューボタン(左右どちらでも)でメニューを開く・閉じる。中身は M2 の項 |

グリップは空けておき、後からリセットなどに割り当てる。メニューボタンは M2 で「メニューを開く」に割り当てる(全種目共通。CLAUDE.md の入力割り当ての表もこれに合わせて更新する)。

## ゲームモードと成長要素

初期は1人用とCPU対戦だけにし、オンライン対戦は種目がそろってから検討する。ネットワーク対戦は工数が大きく、1種目目の完成を遅らせるためである。

| モード | 内容 | 時期 |
| --- | --- | --- |
| フリープレイ | 好きな種目を1人で遊ぶ(ハブから選ぶのは M2) | M1 |
| チャレンジ | 種目ごとの課題(例:ピンを指定本数だけ倒す) | M3 |
| CPU対戦 | 強さ3段階のCPUと対戦 | M3 |
| 交代プレイ | 1台のヘッドセットを回して家族・友人と得点を競う | M3 |
| オンライン対戦 | 離れた相手とリアルタイム対戦 | 将来検討 |

成長要素は「腕前ポイント」1本にまとめる。勝敗とスコアでポイントが上下し、種目ごとのランク(ブロンズ〜プラチナ)で上達が見える形にする。報酬は見た目のみ(ボールの柄、弓の色、アバターの帽子など)とし、強さには影響させない。腕前ポイントとランクは M2、見た目のご褒美は M4 で入れる。

### 腕前ポイントとランク(M2)

ポイントは種目ごとに持ち、0 から始める。1ゲームを最後まで遊んだときだけ増減し、途中でハブへ戻ったゲームは数えない。

1ゲームの増減 = 完走ボーナス +5 + (スコア − 今のランクの基準スコア) ÷ 割る数(四捨五入)。ただし後ろの項は −20〜+40 に収める。

| 種目 | 割る数 | 基準スコア(ランク1 / 2 / 3 / 4) |
| --- | --- | --- |
| ボウリング(満点300) | 2 | 70 / 110 / 150 / 190 |
| アーチェリー(満点180) | 1.5 | 60 / 90 / 120 / 150 |

例:ボウリングでランク1のとき 100点なら +5 + 15 = +20、40点なら +5 − 15 = −10。

| ランク | 名前 | 必要ポイント | 相当 |
| --- | --- | --- | --- |
| 1 | かいがら | 0〜 | ブロンズ |
| 2 | さんご | 100〜 | シルバー |
| 3 | しんじゅ | 300〜 | ゴールド |
| 4 | にじいろ | 600〜 | プラチナ |

- ランクは下がらない。ポイントは減るが、今のランクの必要ポイントより下にはならない(個人で遊ぶため、上達の記録として見せる)
- ポイントの上限はない。にじいろの中ではポイントの数字だけが増える
- 表示する場所:ハブの種目の看板(ランク・ポイント・ベスト)、各種目の結果(増減・ランクアップの知らせ)
- 基準スコア・割る数・増減の範囲・必要ポイントは Inspector(1つの設定アセット)で調整できるようにする
- メダルの見た目は `docs/art-direction.md`(6.3、M2 の項)

## 世界観・アート・サウンド

アートは「明るいローポリ+柔らかい陰影」のスタイライズド路線にする。リアル寄りは8KXの高解像度で描画が重くなり、個人の制作量でも破綻しやすい。ローポリなら無料のアセット(CC0素材)と組み合わせても見た目の統一感を出しやすい。

- 舞台:空に浮かぶ小さな南国の島。中央の広場(ハブ)から各種目の会場へ歩いて行ける
- 会場:海辺のボウリング小屋(室内・2レーン)、森の中のアーチェリー場、ヤシの木陰の卓球台
- 時間帯:朝・昼・夕焼けの3パターン。焼き込みライティング(ライトマップ)で軽く見せる
- アバター:頭と手だけの簡易表示から始める。全身アバターは腕の動きが不自然になりやすく後回し
- 観客:丸みのあるデフォルメ人形風。表情はテクスチャの差し替えで表現
- CPU対戦の相手:ユーザー本人が作った女の子の VRM モデル(M3。詳細は M3 の項)

- 時間帯の切り替え(朝・昼・夕焼け)は M4。M1〜M3 は昼の1パターンで進める
- サウンド:波と鳥の環境音を常時流し、ストライクや的の中心に当たったときの効果音を大きめにして「気持ちよさ」を強調する。プレイ中は BGM を流さない

カラーパレット、描画負荷の予算、3Dモデルと音素材の調達先・ライセンス、ライティング、UI の見た目、演出、音の詳細は `docs/art-direction.md` にまとめる。

## 快適性と安全設計

VR酔いの最大の原因は「自分が動いていないのに視界が動く」ことなので、カメラを勝手に動かす演出は一切入れない。種目の多くを「その場から動かない」ものにしたのもこのためである。

- 移動:ハブ内の移動はテレポート(指した場所に瞬間移動)を基本にする。連続移動は設定で切り替えるオプションとし、オンのときはテレポートの代わりにトラックパッドに触れた方向へ移動する(M2 で実装)。ボウリングではテレポート先をファウルラインより手前の助走路に限り、レーンの上や横へは出られないようにする(M1)
- 向きの変更:スナップターン(一定角度ずつ回る)を標準にする(テレポートとともに M0 で実装)
- 場面の切り替え:ハブと会場の行き来はシーンの切り替えにし、0.3秒かけて暗い色へフェードアウト、読み込みが終わってから 0.3秒でフェードイン。フェード中もカメラは頭の動きに追従させ、視点を引っぱる移動は入れない(M2。フェードの色は `docs/art-direction.md`)
- 演出:ストライク時などもカメラは揺らさず、周りのエフェクトで盛り上げる
- 腕振り:強く振る種目では、プレイ開始前に「周りに人や物がないか確認」の表示を出す(M1)
- 手放し防止:最初にストラップを手首に付ける案内を表示する(コントローラーが飛ぶ事故対策。M1)
- 休憩:20分ごとに軽い休憩の案内を出す(オフ可能。M2)
- 身長差:身長と利き手を最初に設定し、ボウリングのレーン、アーチェリーの的、卓球台の高さを合わせる(M1。保存は M2)

## 技術構成

Unity 6(6000.6.7f1)+ OpenXR + XR Interaction Toolkit の標準構成で作る。OpenXR にしておけば、Pimax(SteamVR経由)でもコントローラーの種類の違いを吸収しやすい。

| 領域 | 採用技術 | 理由 |
| --- | --- | --- |
| エンジン | Unity 6(6000.6.7f1) | 情報が多く、PC VR向けの実績が豊富 |
| XR基盤 | OpenXR(SteamVR ランタイム) | Pimaxと各種コントローラーに対応できる |
| 操作 | XR Interaction Toolkit | 掴む・投げる・テレポートが標準部品で揃う |
| 描画 | URP(ユニバーサルレンダーパイプライン) | 8KXの高解像度でもフレームレートを保ちやすい |
| 物理 | Unity標準物理 + 卓球のみ自作の衝突計算 | 高速なボールのすり抜け対策 |
| 保存 | 端末内のJSONファイル | スコア・ランク・設定を保存 |
| オンライン | 未定(将来、Netcode for GameObjects などを検討) | MVPでは使わない |

リポジトリ(shuji30/vrgame3)のフォルダは種目ごとに分け、共通部品と混ぜないようにする。

```
Assets/
  _Project/
    Common/       … 掴む・投げる処理、設定、スコア保存、効果音管理
    Hub/          … 島の広場、種目選択
    Sports/
      Bowling/    … シーン、スクリプト、モデル
      Archery/
      TableTennis/
    Art/          … 共有パレット、共通マテリアル
  ThirdParty/     … 外部アセット
```

モデルやテクスチャが増えて容量が大きくなってきたら、Git LFS を導入する。

## 開発ロードマップ

M1でボウリングを「人に遊んでもらえる」状態にすることが最初のゴールで、各段階の終わりのゲートを越えるまで次の種目には進まない。締め切りは設けず、ゲートを越えたら次へ進む。

フレームレートの基準は全段階で 60fps とし、SteamVR のフレームタイミング表示で確かめる。各段階の作業は M1 のゲートに必要かどうかで振り分け、不要なものは後ろへ回す。

### M0 準備

作業:

- `Assets/_Project/` 以下のフォルダ(Common / Hub / Sports / Art)を作る
- テンプレートのサンプル(SampleScene、TutorialInfo、Readme.asset)を整理する
- 導入済みの OpenXR・XR Interaction Toolkit で XR Origin を配置し、HTC Vive Controller Profile を設定する
- トラックパッドの振り分けを作る(押し込んだ瞬間のタッチ位置 X で、中央=テレポート、左右=スナップターン。しきい値と角度は Inspector で調整)
- 全種目で使う「掴む・投げる」の共通部品を作る
- 頭と手のアバター表示を入れる

#### 設定と保存

| 項目 | 内容 |
| --- | --- |
| 保存先 | `Application.persistentDataPath` の JSON ファイル1つ。書くときは一時ファイルに書いてから置き換える。読めないときは元のファイルを別名で残して初期値で始める |
| 保存する設定 | 身長(cm)、利き手、連続移動(オン/オフ)、連続移動の速さ、休憩案内(オン/オフ)、アーチェリーのねらいの補助(オン/オフ) |

| 保存するとき | 設定を変えたとき、ゲームが最後まで終わったとき |
| 設定パネル | 共通の部品1つ。中身は身長・利き手・連続移動(オン/オフ・速さ3段)・休憩案内(オン/オフ)。ハブの「せってい」看板とメニューの「せってい」から開く |
| 「はじめに」パネル | ボウリングのパネルを共通部品にし、アーチェリーでも使う。保存した身長・利き手を最初から表示し、毎ゲームの始めに周囲確認とストラップの案内を出す(他の人が遊ぶため)。アーチェリーのパネルにはねらいの補助のオン/オフを足す |

#### 連続移動

| 項目 | 内容 |
| --- | --- |
| オンのとき | テレポートは使えない。利き手でない方のトラックパッドに触れている間、触れた方向へ移動する(上=前、下=後ろ、左右=横)。利き手の方のトラックパッドは移動に使わない |
| スナップターン | オンでも左右の押し込みで回る(両手とも)。押し込んでいる間は移動しない |
| 向きの基準 | 移動する手のコントローラーの向き(水平に直したもの)。頭の向きを基準にする切り替えを Inspector に用意する |
| 速さ | タッチ位置が中心から 0.2 以内は止まる。それより外は距離に比例し、0.9 以上で最大。最大は おそい 1.5 / ふつう 2.0 / はやい 2.5 m/秒(既定は ふつう)。加速・減速の時間は付けない |
| 行ける範囲 | テレポートと同じ。移動先の真下が TeleportArea でなければ進まない(ボウリングは助走路だけ、アーチェリーは射つ位置だけ、ハブは広場)。壁は通り抜けない |
| 設定の場所 | 共通の設定パネル。既定はオフ |
| 入れないもの | 視野を狭める酔い対策の演出。試遊で酔いの指摘が出たら M3 で検討する |

#### 休憩案内

| 項目 | 内容 |
| --- | --- |
| 数え方 | アプリを起動してからの実時間で数え、案内を閉じたら 0 に戻す。間隔は既定 20分(Inspector で変えられる。確認用に 1分にもできる) |
| 出すとき | 間隔を過ぎたあと、最初の区切りで出す。区切りは、ボウリングの1フレームの終わり、アーチェリーのラウンドの終わり、各種目の結果、ハブにいる間 |
| 出し方 | 頭の正面 1.2m、目の高さより少し下に、文字のパネルを1回だけ置く(頭に追従させない)。小さな知らせの音を1回(音は `docs/art-direction.md`) |
| 文 | 「20分あそびました。ひと休みしませんか?」(分は間隔に合わせる) |
| 消し方 | 「とじる」を押す。押すまでは出したまま。ゲームは止めず、出ている間は物を掴めない |
| オフ | パネルの「今後は出さない」か、共通の設定パネルの休憩案内でオフ。既定はオン |

ゲート:

### M3 卓球とCPU対戦

作業:

- 卓球の専用当たり判定(連続衝突判定)
- 強さ3段階のCPU対戦
  - 相手はユーザー本人が作った女の子の VRM モデル(vrgame2 の `games/sky-runner/assets/girl.vrm`、VRM 1.0)。作者本人のみ利用可・改変禁止のため、モデル自体は編集しない
  - ボウリングは「交互にフレーム」で進める。自分が1フレーム投げたら、隣のレーンで相手が1フレーム投げる(相手の投げる姿を見せるのが狙い)
  - 技術メモ:VRM の読み込み(UniVRM)と、投げる・待機・喜ぶなどの人型アニメーションの調達が必要
- 交代プレイ(1台のヘッドセットを回して得点を競う)
- チャレンジモード(種目ごとの課題)
- 3種目そろって「ゲーム集」として成立させる

ゲート:

- 卓球で強く打ち返しても、ボールがラケットをすり抜けない
- CPUの3段階で、強さの違いが遊んで分かる
- 3種目を通して遊んでも 60fps を保つ
- 試遊で酔い・事故の指摘がない

## リスクと対策

最大のリスクは「種目を広げすぎて1つも完成しない」ことで、対策は1種目ずつ遊べる状態まで仕上げてから次へ進むことに尽きる。

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 種目を広げすぎる | 未完成のまま止まる | M1でボウリングを完成させるまで他種目に着手しない |
| 投げる感触が気持ちよくない | 遊びの核が成立しない | M1で手触りの調整に最も時間を使い、他人にも試してもらう |
| 8KXの高解像度で処理落ち | 酔い・不快感 | 毎週実機で 60fps を保てているか確認し、M0 以降の全ゲートに fps の条件を入れる。ローポリと共有パレットで負荷を抑える |
| 卓球の当たり判定 | ボールのすり抜け | 卓球は3種目目に回し、それまでに物理の知見をためる |
| M1 の試遊を後回しにした | 投げ心地や安全の問題が遅れて見つかり、ボウリングの手直しが M2 に食い込む | 試遊は M2 の実装順4(アーチェリーのルール)が終わった時点で一度行ってよい。ボウリングの指摘は Inspector の値で直せるものを先に直す |
| 弓の操作が分かりにくい | 初めての人が矢を放てない | つがえる距離・ねらいの補助を Inspector で調整できるようにし、試遊で最初の1本を放つまでの様子を見る |
| 参考作品に似すぎる | 権利面の問題 | 個人で遊ぶ範囲なので影響は小さい。名称・キャラはオリジナルにしておく |
