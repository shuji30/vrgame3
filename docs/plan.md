# VRスポーツリゾート 企画書(vrgame3)

2026-10-15 作成 / 2026-11-03 更新(M2・M3・M4 の具体化)

## 企画概要

南国の島リゾートを舞台に、手や体を実際に動かして遊ぶ「体感スポーツ集」をVRで作る。最初はボウリング1種目を完成させ、種目を1つずつ足していく。

| 項目 | 内容 |
| --- | --- |
| タイトル案(仮) | 未定(候補は下記) |
| ジャンル | VRスポーツ・ミニゲーム集 |
| 一言で言うと | 島のリゾートで、気軽に何度でも遊べるスポーツをVRで「本当に体を動かして」楽しむ |
| 1プレイ時間 | 1種目 3〜10分 |
| 体験の核 | 投げる・打つ・引くが自分の手の動きそのままに反映される気持ちよさ |

参考作品(Switch Sports / Wii Sports Resort 系)から借りるのは「誰でもすぐ遊べる操作」「短時間で終わる種目」「リゾートの明るい雰囲気」の3点に限る。キャラクター・名称・デザインは完全オリジナルにする。

差別化はVRならではの3点に置く。

- 手の位置と向きが1対1で反映されるため、フォームの上達がそのまま上手さになる
- 島の景色に囲まれる没入感(海、ヤシの木、夕焼けの時間帯変化)
- 種目間を島の中で歩いて移動する「ハブ空間」で、ゲーム集でも一つの場所にいる感覚を出す

### タイトル候補

| 候補 | 意味・由来 | 印象 |
| --- | --- | --- |
| ソラシマ・スポーツリゾート | 空に浮かぶ島(空島)のリゾート | 舞台がそのまま伝わる |
| アイランド・アクティブ | 島で体を動かす | 短く覚えやすい |
| ココナッツ・リーグ | 南国の果物とリーグ戦 | かわいく親しみやすい |
| サンセット・スポーツ | 夕焼けの島で遊ぶ | 雰囲気重視、落ち着いた印象 |
| ハレバレ・アイランド | 晴れ晴れとした島 | 明るく、日本語の響きが楽しい |
| ナミノリ・スポーツ | 海辺で波に乗るような爽快さ | 海の印象が強い |

「スポーツリゾート」は参考作品の名前に近いが、個人で遊ぶ範囲なら問題はない。

## ターゲットとプラットフォーム

対象は PC VR の Pimax 8KX(および他のPimaxシリーズ)で、自分で遊ぶための個人制作とする。ストア公開はしないので、審査や他機種への対応は考えなくてよい。

| 項目 | 方針 |
| --- | --- |
| 想定プレイヤー | 自分(家族や友人が試すこともある) |
| 対応デバイス | Pimax 8KX / Pimaxシリーズ(SteamVR経由) |
| 実行環境 | Windows PC(自宅PCは RTX 4070 Ti) |
| プレイ姿勢 | 立ってその場で遊ぶ。座りプレイも可能な種目を用意 |
| 必要スペース | 2m × 2m 程度、ベースステーションの検知範囲内 |
| 入力 | HTC Vive コントローラー(OpenXR の HTC Vive Controller Profile) |
| 目標フレームレート | 60fps 以上。ヘッドセットのリフレッシュレートも、設定できるなら 60Hz に合わせる(実機で要確認)。8KXは解像度が非常に高いため、描画負荷を抑えることを最優先にする |

## 種目ラインナップ

最初に作るのはボウリング、次にアーチェリー、卓球の順とする。「その場から動かない」「物理が単純」な種目ほど、個人開発でも完成度を上げやすく、VR酔いも起きにくい。

| 優先 | 種目 | VRとの相性 | プレイヤー移動 | 物理の難しさ | 一言メモ |
| --- | --- | --- | --- | --- | --- |
| 1 | ボウリング | 高 | なし | 低 | 投げる動作が直感的。MVPに最適 |
| 2 | アーチェリー | 高 | なし | 低 | 弦を引く手応えがVR向き。的当てで得点が明快 |
| 3 | 卓球 | 非常に高 | なし | 高 | 一番VRらしいが、高速ボールの当たり判定が難所 |
| 4 | パターゴルフ | 高 | 少し(ワープ) | 中 | 座ってもできる。コース作りが楽しい |
| 5 | フリスビー | 中 | なし | 中 | 投げて犬がキャッチ。島の雰囲気づくりに合う |
| 6 | 剣のチャンバラ | 中 | なし | 中 | 対CPU戦。手応え(当たったときの反発)の表現が課題 |
| 7 | テニス | 中 | 自動移動 | 高 | 自分で走れないため自動移動が必要。後回し |
| 8 | カヌー | 低 | 常に移動 | 中 | 景色は良いがVR酔いしやすい。オプション扱い |

種目数は3つそろった時点で「ゲーム集」として成立させ、4つ目以降は反応を見て決める。

## コアゲームプレイと操作設計

全種目で「トリガーを引いている間だけ掴み、離して投げる/放つ」を共通操作にし、説明なしで遊べるようにする。投げる速さと向きは、手を離した瞬間のコントローラーの速度から計算する。

### ボウリング(MVP)

1. ボール置き場でトリガーを引いてボールを掴む
2. レーンに向かって腕を振り、トリガーを離して投げる
3. 離した瞬間の手の速度でボールの速さ、手首のひねりで回転(カーブ)が決まる
4. 10フレームでスコアを競う。ストライク・スペアの演出で気持ちよさを出す

調整ポイントは次の3つ。

- 投げる力の補正:実際の腕振りは小さいので、速度に倍率をかけて「強く投げた感」を出す
- 床への投げつけ防止:手が床より下に行ってもボールは床の上から出る
- 投げ損ね救済:ファウルラインより手前に落ちたら自動で転がす

### アーチェリー

片手で弓を持ち、もう片方の手で弦を掴んで引き、離して矢を放つ。引いた距離で矢の速さが決まり、重力で山なりに飛ぶ。弦を引いている間はコントローラーを細かく振動させて手応えを出す(強さは `docs/art-direction.md` 8.8)。M2 で入れる。

操作(Vive ワンド。割り当ては共通のまま、グリップは使わない):

| 手 | 操作 |
| --- | --- |
| 弓を持つ手(利き手でない方) | 「はじめる」を押すと弓がこの手に付く。トリガーを引き続けなくてよい(持ち疲れ防止)。ゲームが終わるかハブへ戻ると外れる |
| 矢を引く手(利き手) | 手を弦の中央(矢をつがえる点)から 0.12m 以内に近づけてトリガーを引くと、矢が現れて弦を掴む。矢筒から取る動作はない |
| 引く | トリガーを引いたまま手を後ろへ引く。引いた距離は弦の中央からの距離で測り、最大 0.6m で止める |
| 放つ | トリガーを離す。引いた距離が 0.1m 未満なら矢は消え、本数を減らさない(空撃ち扱い) |

- 利き手は共通の設定を使い、左利きなら左右を入れ替える
- 矢の速さは、引いた距離 0.1〜0.6m を 15〜45m/秒に比例させる。重力は標準(9.81)
- 矢は飛んでいる向きに先を向け、前のフレームの位置からのレイで当たりを取る(高速ですり抜けないため)
- 刺さった矢はラウンドの終わりまで残し、次のラウンドの始めに消す。的の外へ飛んだ矢は 5秒で消す
- 射つ位置は射線の後ろ 1.5m × 1.5m に限る(TeleportArea で囲う)

ルール:

| 項目 | 内容 |
| --- | --- |
| 1ゲーム | 3ラウンド × 6本 = 18本。時間制限なし。1ゲーム 4〜6分の目安 |
| 的までの距離 | 1ラウンド目 10m、2ラウンド目 20m、3ラウンド目 30m。的は1つで、ラウンドの始めに次の距離へ置き直す(プレイヤーは動かない) |
| 的 | 直径 1.2m、10個のリング(1リング幅 6cm)。中心の高さは身長設定 × 0.85(170cm で約 1.45m) |
| 点数 | 中心から 10・9・…・1 点、的の外・地面は 0 点。線に掛かったら高い方。満点 180 |
| 中心(X) | 10点リングの内側半分(直径 6cm)は「X」として記録し、特別な演出と音を出す(点は10のまま。演出と音は `docs/art-direction.md`) |
| 表示 | 射つ位置の横の小型スコア板に、ラウンドごとの6本の点・ラウンド合計・総合計・残り本数。当たった矢の点は的の横にも数秒出す |
| 終わり方 | 18本目が刺さる(または消える)と結果を出す:総合計、ベスト(更新なら印)、腕前ポイントの増減とランク。結果の下に「もういちど」「ハブへ」 |

狙いやすさの補助(初心者向け):

- 「ねらいの補助」をアーチェリーの「はじめに」パネルでオン/オフでき、既定はオン。値は保存する
- オンのとき、弦を引いている間だけ、矢の飛ぶ道筋の最初の 4m を点線で出す(長さは Inspector で調整)。的に届くところまでは出さず、向きと山なりの具合だけ分かるようにする
- 補助のオン/オフでスコアとポイントの扱いは変えない(個人で遊ぶため)

調整できるようにする値(Inspector):つがえる距離、最大の引き、矢の速さの下限・上限、重力の倍率、的の距離3つ、的の直径、補助線の長さ、振動の強さ。

### 卓球

ラケットは手に持ったまま固定し、ボールとの当たり判定はラケットの速度と向きで反射を計算する。物理エンジン任せにすると高速ボールがすり抜けるため、専用の衝突計算(連続衝突判定)を自作する前提で、最も工数を見ておく。M3 で入れる。相手は常に CPU(CPU の作り方は M3 の項)。

操作(Vive ワンド。割り当ては共通のまま、グリップは使わない):

| 手 | 操作 |
| --- | --- |
| ラケットの手(利き手) | 「はじめる」を押すとラケットがこの手に付く。トリガーを引き続けなくてよい(持ち疲れ防止。弓と同じ)。ゲームが終わるかハブへ戻ると外れる |
| ボールの手(利き手でない方) | 自分のサーブの番にトリガーを引くと、手の中にボールが現れて持つ。トリガーを離すと手の速さのままボールが離れる(真上に軽く投げ上げる)。サーブの番以外は何も起きない |
| 打つ | ラケットを振ってボールに当てる。ボタンは使わない |

- 利き手は共通の設定を使い、左利きなら左右を入れ替える
- ラケットの付く位置と角度(コントローラーからのずれ)は Inspector で調整する。目安は、面の中心がコントローラーの指す向きへ 0.12m、ワンドの柄がそのままラケットの柄になる向き
- ボールは拾わない。床に落ちたボールは1秒後に消え、次のサーブで手元に現れる(床に手を伸ばさせないため)
- ラケットを持っていても、メニューとパネルはこれまでどおりレイで指してトリガーで押せる

ボールの動き(物理エンジンを使わず、専用の計算で動かす):

| 項目 | 内容 |
| --- | --- |
| 大きさ | 直径 0.04m(見た目と当たりは同じ) |
| 重力・空気 | 重力 9.81。空気の抵抗は速さの2乗に比例(係数の目安 0.14)。回転(カーブ・ドライブ)は入れない |
| 進め方 | 毎フレーム、細かい刻み(目安 1/240 秒)に分けて進める。台・ネット・床は平面と箱として計算で当てる |
| 台で弾む | 縦の跳ね返り 0.88、横の速さは 0.95 倍 |
| ネット | 当たると縦横とも大きく減速(跳ね返り 0.1)。越えたかどうかはそのまま判定に使う |
| ラケットとの当たり | 前のフレームと今のフレームのラケットの位置・向きを刻みごとに補間し、ボールが面を通り越したかで当たりを取る(連続衝突判定)。面の当たりの広さは見た目の 1.1 倍 |
| 打ち返す速さ | ボールとラケットの相対速度を面の向きで反射(跳ね返り 0.85)し、ラケットの速さ(回転による先端の速さも含む)を足す。ラケットの速さは直近 2〜3 フレームの平均。打つ力の倍率 1.0、ボールの最高速 25m/秒 |
| 二度当たり | 当たった後 0.15 秒は同じラケットに当たらない |
| 迷子 | 台から 8m 以上離れたか、10 秒たっても決着しないボールは消し、最後に打った側の失点にする |

入りやすさの補助(初心者向け、アーチェリーのねらいの補助と同じ扱い):

- 卓球の「はじめに」パネルでオン/オフでき、既定はオン。値は保存する
- オンのとき、自分が打った球が「もう少しで相手コートに入る」とき(落ちる点が台の外 0.3m 以内、またはネットの上を 0.1m 以内の差で越えられない)だけ、向きを最大 6°・速さを最大 15% 直して台の中(縁から 0.1m 内側)・ネットの上 0.05m に入れる。大きく外れた球は直さない
- 補助のオン/オフでスコアとポイントの扱いは変えない

ルール(本物より簡単にする):

| 項目 | 内容 |
| --- | --- |
| 1ゲーム | 11点先取。10対10 からは2点差がつくまで続ける(デュース)。1ゲームだけで勝敗を決める。1ゲーム 4〜8分の目安 |
| サーブ | 最初はプレイヤー。2点ごとに交代し、デュースでは1点ごとに交代する |
| サーブの入り方 | 相手のコートに入ればよい。直接入っても、自分のコートに1回弾んでから入ってもよい。ネットに触れて入っても有効(打ち直しはない) |
| サーブのやり直し | 投げ上げたボールにラケットが当たらずに落ちたときは失点にせず、もう一度ボールが現れる。回数の制限はない |
| 得点になるとき | 打った球が相手のコートに入らずに床・自分のコート・台の外へ落ちた/相手のコートで2回弾んだ/相手が返せずに床に落ちた/迷子 |
| 打つ前のバウンド | プレイヤーは自分のコートで弾む前に打ってもよい(反則にしない)。CPU は必ず1回弾んでから打つ |
| 1点の終わり | 決着から1秒でボールを消し、スコア板を更新する。次のサーブがプレイヤーならボールの手のトリガー待ち、CPU なら 1.5 秒後に CPU が打つ |
| 表示 | 台の横のスコア板に、両者の点・サーブ権の印・CPU の強さ。決着したときに「アウト」「ネット」「2バウンド」など理由を短く出す |
| 終わり方 | どちらかが勝つと結果を出す:勝敗と点数、卓球スコア(腕前ポイントの項)、ベスト、腕前ポイントの増減とランク。結果の下に「もういちど」「ハブへ」 |

- 台の高さは 0.76m × 身長 ÷ 170(0.68〜0.84m に収める)
- 動ける範囲は自分の側の台の後ろだけにする。TeleportArea は台の端から 0.3〜2.5m 後ろ、台の中心から左右 1.5m。開始位置は台の端から 0.7m 後ろの中央。ネットの向こう(CPU 側)と台の上には出られない
- メニューか休憩案内が開いたら、ラリー中のボールを消し、その1点はなかったことにして同じサーブからやり直す(時間は止めない決まりのままにするため)
- 「はじめに」パネルの周囲確認に「台はほんものではありません。手をついたり、もたれたりしないでください」を足す

調整できるようにする値(Inspector):ラケットの位置と角度、面の当たりの広さ、打つ力の倍率、ボールの最高速、重力と空気の係数、台・ネット・床の跳ね返り、刻みの細かさ、補助の範囲と直す量、先取点、台の高さの基準、CPU の強さ3段階の値(M3 の項)、振動の強さ。

### コントローラー

操作は HTC Vive コントローラー(Vive ワンド)に統一し、ハンドトラッキングは使わない。ボタンの割り当ては全種目で共通にする。

| 操作 | 割り当て |
| --- | --- |
| 掴む・離す | トリガー(引いている間だけ掴む) |
| テレポート | トラックパッドの中央を押し込み。押している間に放物線を表示し、離した地点へ移動 |
| スナップターン | トラックパッドの左右を押し込み |
| 連続移動(オプション) | 設定でオンにしたときだけ、テレポートの代わりにトラックパッドに触れた方向へ移動 |
| メニュー(M2) | メニューボタン(左右どちらでも)でメニューを開く・閉じる。中身は M2 の項 |

グリップは空けておき、後からリセットなどに割り当てる。メニューボタンは M2 で「メニューを開く」に割り当てる(全種目共通。CLAUDE.md の入力割り当ての表もこれに合わせて更新する)。

## ゲームモードと成長要素

初期は1人用とCPU対戦だけにし、オンライン対戦は種目がそろってから検討する。ネットワーク対戦は工数が大きく、1種目目の完成を遅らせるためである。

| モード | 内容 | 時期 |
| --- | --- | --- |
| フリープレイ | 好きな種目を1人で遊ぶ(ハブから選ぶのは M2) | M1 |
| チャレンジ | 種目ごとの課題3つ(例:ピンを指定本数だけ倒す) | M3 |
| CPU対戦 | 強さ3段階のCPUと対戦(卓球・ボウリング) | M3 |
| 交代プレイ | 1台のヘッドセットを回して家族・友人と得点を競う(ボウリング・アーチェリー) | M3 |
| オンライン対戦 | 離れた相手とリアルタイム対戦 | 将来検討 |

成長要素は「腕前ポイント」1本にまとめる。勝敗とスコアでポイントが上下し、種目ごとのランク(ブロンズ〜プラチナ)で上達が見える形にする。報酬は見た目のみ(ボールの柄、弓の色、ラケットの色、手袋の色)とし、強さには影響させない。腕前ポイントとランクは M2、見た目のご褒美は M4 で入れる(M4 の「見た目のご褒美」)。

### 腕前ポイントとランク(M2)

ポイントは種目ごとに持ち、0 から始める。1ゲームを最後まで遊んだときだけ増減し、途中でハブへ戻ったゲームは数えない。

1ゲームの増減 = 完走ボーナス +5 + (スコア − 今のランクの基準スコア) ÷ 割る数(四捨五入)。ただし後ろの項は −20〜+40 に収める。

| 種目 | 割る数 | 基準スコア(ランク1 / 2 / 3 / 4) |
| --- | --- | --- |
| ボウリング(満点300) | 2 | 70 / 110 / 150 / 190 |
| アーチェリー(満点180) | 1.5 | 60 / 90 / 120 / 150 |
| 卓球(卓球スコア、最高 144。M3) | 1 | 40 / 70 / 100 / 130 |

例:ボウリングでランク1のとき 100点なら +5 + 15 = +20、40点なら +5 − 15 = −10。

卓球スコア = CPU の強さの点(やさしい 0 / ふつう 40 / つよい 80)+ 自分の得点 × 4(11点まで数える)+ 勝ったら 20。

- 例:ランク1で やさしいに 11対5 で勝つと 64 → +5 + 24 = +29。ランク3で ふつうに 9対11 で負けると 76 → +5 − 20(下限)= −15
- 上のランクほど強い CPU に挑まないとポイントが増えにくい形にする
- ベストは卓球スコアで保存し、ハブの看板にもその数字を出す。結果では内訳(強さ・得点・勝ち)も出す
- ボウリングの CPU 対戦は1人のときと同じ(自分のスコアだけで計算し、勝敗は使わない)。交代プレイとチャレンジはポイントを動かさない

| ランク | 名前 | 必要ポイント | 相当 |
| --- | --- | --- | --- |
| 1 | かいがら | 0〜 | ブロンズ |
| 2 | さんご | 100〜 | シルバー |
| 3 | しんじゅ | 300〜 | ゴールド |
| 4 | にじいろ | 600〜 | プラチナ |

- ランクは下がらない。ポイントは減るが、今のランクの必要ポイントより下にはならない(個人で遊ぶため、上達の記録として見せる)
- ポイントの上限はない。にじいろの中ではポイントの数字だけが増える
- 表示する場所:ハブの種目の看板(ランク・ポイント・ベスト)、各種目の結果(増減・ランクアップの知らせ)
- 基準スコア・割る数・増減の範囲・必要ポイントは Inspector(1つの設定アセット)で調整できるようにする
- メダルの見た目は `docs/art-direction.md`(6.3、M2 の項)

## 世界観・アート・サウンド

アートは「明るいローポリ+柔らかい陰影」のスタイライズド路線にする。リアル寄りは8KXの高解像度で描画が重くなり、個人の制作量でも破綻しやすい。ローポリなら無料のアセット(CC0素材)と組み合わせても見た目の統一感を出しやすい。

- 舞台:空に浮かぶ小さな南国の島。中央の広場(ハブ)から各種目の会場へ歩いて行ける
- 会場:海辺のボウリング小屋(室内・2レーン)、森の中のアーチェリー場、ヤシの木陰の卓球台
- 時間帯:朝・昼・夕焼けの3パターン。まずリアルタイムの太陽・環境光・空・霧の切り替えで作り、焼き込みライティング(ライトマップ)は完成のあとの任意の作業にする(M4 の「時間帯」)
- アバター:頭と手だけの簡易表示から始める。全身アバターは腕の動きが不自然になりやすく後回し
- 観客:丸みのあるデフォルメ人形風。表情はテクスチャの差し替えで表現
- CPU対戦の相手:ユーザー本人が作った女の子の VRM モデル(M3。詳細は M3 の項)

- 時間帯の切り替え(朝・昼・夕焼け)は M4。M1〜M3 は昼の1パターンで進める
- サウンド:波と鳥の環境音を常時流し、ストライクや的の中心に当たったときの効果音を大きめにして「気持ちよさ」を強調する。プレイ中は BGM を流さない

カラーパレット、描画負荷の予算、3Dモデルと音素材の調達先・ライセンス、ライティング、UI の見た目、演出、音の詳細は `docs/art-direction.md` にまとめる。

## 快適性と安全設計

VR酔いの最大の原因は「自分が動いていないのに視界が動く」ことなので、カメラを勝手に動かす演出は一切入れない。種目の多くを「その場から動かない」ものにしたのもこのためである。

- 移動:ハブ内の移動はテレポート(指した場所に瞬間移動)を基本にする。連続移動は設定で切り替えるオプションとし、オンのときはテレポートの代わりにトラックパッドに触れた方向へ移動する(M2 で実装)。ボウリングではテレポート先をファウルラインより手前の助走路に限り、レーンの上や横へは出られないようにする(M1)
- 向きの変更:スナップターン(一定角度ずつ回る)を標準にする(テレポートとともに M0 で実装)
- 場面の切り替え:ハブと会場の行き来はシーンの切り替えにし、0.3秒かけて暗い色へフェードアウト、読み込みが終わってから 0.3秒でフェードイン。フェード中もカメラは頭の動きに追従させ、視点を引っぱる移動は入れない(M2。フェードの色は `docs/art-direction.md`)
- 演出:ストライク時などもカメラは揺らさず、周りのエフェクトで盛り上げる
- 腕振り:強く振る種目では、プレイ開始前に「周りに人や物がないか確認」の表示を出す(M1)
- 手放し防止:最初にストラップを手首に付ける案内を表示する(コントローラーが飛ぶ事故対策。M1)
- 休憩:20分ごとに軽い休憩の案内を出す(オフ可能。M2)
- 身長差:身長と利き手を最初に設定し、ボウリングのレーン、アーチェリーの的、卓球台の高さを合わせる(M1。保存は M2)

## 技術構成

Unity 6(6000.6.7f1)+ OpenXR + XR Interaction Toolkit の標準構成で作る。OpenXR にしておけば、Pimax(SteamVR経由)でもコントローラーの種類の違いを吸収しやすい。

| 領域 | 採用技術 | 理由 |
| --- | --- | --- |
| エンジン | Unity 6(6000.6.7f1) | 情報が多く、PC VR向けの実績が豊富 |
| XR基盤 | OpenXR(SteamVR ランタイム) | Pimaxと各種コントローラーに対応できる |
| 操作 | XR Interaction Toolkit | 掴む・投げる・テレポートが標準部品で揃う |
| 描画 | URP(ユニバーサルレンダーパイプライン) | 8KXの高解像度でもフレームレートを保ちやすい |
| 物理 | Unity標準物理 + 卓球のみ自作の衝突計算 | 高速なボールのすり抜け対策 |
| 保存 | 端末内のJSONファイル | スコア・ランク・設定を保存 |
| VRM の読み込み | UniVRM(VRM10)。入れるかは任意(M3) | CPU の体を girl.vrm にするときだけ使う。無くても仮人形で動く |
| オンライン | 未定(将来、Netcode for GameObjects などを検討) | MVPでは使わない |

リポジトリ(shuji30/vrgame3)のフォルダは種目ごとに分け、共通部品と混ぜないようにする。

```
Assets/
  _Project/
    Common/       … 掴む・投げる処理、設定、スコア保存、効果音管理
    Hub/          … 島の広場、種目選択
    Sports/
      Bowling/    … シーン、スクリプト、モデル
      Archery/
      TableTennis/
    Art/          … 共有パレット、共通マテリアル
  ThirdParty/     … 外部アセット
```

モデルやテクスチャが増えて容量が大きくなってきたら、Git LFS を導入する。

## 開発ロードマップ

M1でボウリングを「人に遊んでもらえる」状態にすることが最初のゴールで、各段階の終わりのゲートを越えるまで次の種目には進まない。締め切りは設けず、ゲートを越えたら次へ進む。

フレームレートの基準は全段階で 60fps とし、SteamVR のフレームタイミング表示で確かめる。各段階の作業は M1 のゲートに必要かどうかで振り分け、不要なものは後ろへ回す。

### M0 準備

作業:

- `Assets/_Project/` 以下のフォルダ(Common / Hub / Sports / Art)を作る
- テンプレートのサンプル(SampleScene、TutorialInfo、Readme.asset)を整理する
- 導入済みの OpenXR・XR Interaction Toolkit で XR Origin を配置し、HTC Vive Controller Profile を設定する
- トラックパッドの振り分けを作る(押し込んだ瞬間のタッチ位置 X で、中央=テレポート、左右=スナップターン。しきい値と角度は Inspector で調整)
- 全種目で使う「掴む・投げる」の共通部品を作る
- 頭と手のアバター表示を入れる
- アート・音:docs/art-direction.md の M0 の項を参照

ゲート(実機で次をすべて満たす):

- 正面の目標に向けて10回投げ、8回以上が狙った方向(目標の左右1m以内)に飛ぶ
- 投げた物・掴んだ物が床や壁をすり抜けない(床に叩きつけても下に落ちない)
- トラックパッド中央の押し込みで狙った地点へテレポートでき、左右の押し込みでスナップターンが誤作動なく効く
- 頭と手が実際の動きに遅れず追従する
- 上の操作中、60fps を保つ

### M1 ボウリング完成(MVP)

作業:

- 2レーンの小屋で自分のレーン1つを使い、10フレーム・スコア表示・ストライク演出(2レーン目は並ぶだけで使わない。M3 の CPU 対戦で使う)
- テレポート先をファウルラインより手前の助走路に限る
- 投げ心地の調整(投げる力の補正、床への投げつけ防止、投げ損ね救済)に一番時間を使う
- 身長・利き手の設定と、レーンの高さ合わせ(設定の保存は M2)
- プレイ開始前の周囲確認とストラップの案内(ゲートで他の人が腕を振るため)
- 環境音・効果音の最低限
- アート・音:docs/art-direction.md の M1 の項を参照

ゲート:

- 自分以外の2人以上に10フレーム通しで遊んでもらい「もう1回」と言われる
- その試遊で、酔い・事故(コントローラーのすっぽ抜け、人や物への接触)の指摘や発生がない
- 試遊の全フレームで 60fps を保つ
- 身長の違う人が遊んでも、設定だけでレーンの高さが合う
- 助走路の外(レーンの上や横)を狙ってテレポートしても移動できない

状況(2026-11-03):実装は完了し、作者が実機で1人10フレーム通して遊べた。上のゲートのうち、他の2人以上の試遊・試遊中の 60fps・身長の違う人・助走路外へのテレポート不可は未確認。ゲート未達のまま M2 に着手する(ユーザー判断、2026-11-03)。これらの確認は M2 の途中か終わりの試遊にまとめて行い、M2 のゲートに含める。

#### 設定と保存

| 入らないもの | 複数人のプロフィール(保存は1人分。交代プレイは M3)、音量の設定(M4) |

#### 連続移動

| 項目 | 内容 |
| --- | --- |
| オンのとき | テレポートは使えない。利き手でない方のトラックパッドに触れている間、触れた方向へ移動する(上=前、下=後ろ、左右=横)。利き手の方のトラックパッドは移動に使わない |
| スナップターン | オンでも左右の押し込みで回る(両手とも)。押し込んでいる間は移動しない |
| 向きの基準 | 移動する手のコントローラーの向き(水平に直したもの)。頭の向きを基準にする切り替えを Inspector に用意する |
| 速さ | タッチ位置が中心から 0.2 以内は止まる。それより外は距離に比例し、0.9 以上で最大。最大は おそい 1.5 / ふつう 2.0 / はやい 2.5 m/秒(既定は ふつう)。加速・減速の時間は付けない |
| 行ける範囲 | テレポートと同じ。移動先の真下が TeleportArea でなければ進まない(ボウリングは助走路だけ、アーチェリーは射つ位置だけ、ハブは広場)。壁は通り抜けない |
| 設定の場所 | 共通の設定パネル。既定はオフ |
| 入れないもの | 視野を狭める酔い対策の演出。試遊で酔いの指摘が出たら M3 で検討する |

#### 休憩案内

| 項目 | 内容 |
| --- | --- |
| 数え方 | アプリを起動してからの実時間で数え、案内を閉じたら 0 に戻す。間隔は既定 20分(Inspector で変えられる。確認用に 1分にもできる) |
| 出すとき | 間隔を過ぎたあと、最初の区切りで出す。区切りは、ボウリングの1フレームの終わり、アーチェリーのラウンドの終わり、各種目の結果、ハブにいる間 |
| 出し方 | 頭の正面 1.2m、目の高さより少し下に、文字のパネルを1回だけ置く(頭に追従させない)。小さな知らせの音を1回(音は `docs/art-direction.md`) |
| 文 | 「20分あそびました。ひと休みしませんか?」(分は間隔に合わせる) |
| 消し方 | 「とじる」を押す。押すまでは出したまま。ゲームは止めず、出ている間は物を掴めない |
| オフ | パネルの「今後は出さない」か、共通の設定パネルの休憩案内でオフ。既定はオン |

- ボウリングの2レーン目の使用、人形(CPU・観客)(M3)

- グリップボタンの割り当て、スナップターン角度の設定画面(Inspector のみ)
- ゲームの一時停止(メニューを開いても時間は進む)

ゲート:

- 起動するとハブに入り、看板から2種目に入れて、メニューと結果の「ハブへ」で戻れる。往復を各種目3回行い、フェード中に視界が固まったり頭と関係なく動いたりしない
- アーチェリー:作者が 10m で6本中4本以上を的に当てられる。30本射って、的に当たった矢が的をすり抜けた数が0

- ハブ→ボウリング10フレーム→ハブ→アーチェリー18本→ハブを通して 60fps を保つ(SteamVR のフレームタイミングで 16.7ms を超える場面を記録し、なければ合格)
- 再起動しても、身長・利き手・連続移動とその速さ・休憩案内・ねらいの補助・両種目のベスト・ポイント・ランクが残っている。保存ファイルを消すと初期値で始まる
- 休憩案内:間隔を1分にして区切りで出ること、「とじる」で消えて次の間隔でまた出ること、オフにすると出ないことを確かめる。既定の20分でも1回出ることを確かめる
- 連続移動オン:テレポートが出ず、触れた方向へ移動し、スナップターンが効き、各会場で行ける範囲の外(レーンの上・射線の先・島の縁)へ出られない
- 自分以外の2人以上にハブから両種目を遊んでもらい、どちらかで「もう1回」と言われる。その試遊で酔い・事故の指摘や発生がない(連続移動オンで1人以上を含む)
- M1 の未確認の項目(身長の違う人でレーンの高さが合う、助走路の外へテレポートできない)を同じ試遊で確かめる

### M3 卓球とCPU対戦

作業は下の実装順で進め、各段階の終わりに実機で動きを確かめてから次へ進む。卓球の操作・ボールの動き・ルールは「コアゲームプレイと操作設計」の卓球の項。

| 1 | 卓球場の仮シーン `TableTennis`(プリミティブの台・ネット・床・TeleportArea)をエディタのメニューで組み立てる。ラケットが手に付く、ボールの専用の動きと連続衝突判定、練習用の球出し(相手側から一定間隔でボールが飛んでくる) | 球出しの球を全力で打ち返してもすり抜けず、軽く当てれば相手コートに返る |

| 3 | ルール(サーブ・判定・得点・サーブ交代・デュース)、スコア板、卓球の「はじめに」パネル(入りやすさの補助を含む)、結果と腕前ポイント、ハブに卓球の看板 | 11点でゲームが終わり、結果とポイントが出て、ハブの看板に残る |

#### 卓球の CPU

体はアニメーションの素材を使わず、スクリプトで動かす。CPU のラケットは物理で当てず、決めた時刻にボールの速さを書き換える。

| 項目 | 内容 |
| --- | --- |
| 予測 | プレイヤーが打った瞬間に、ボールと同じ計算を先回りして進め、CPU 側で1回弾んだ後に打ちやすい高さ(台の上 0.15〜0.35m)を通る位置と時刻を求める |
| 移動 | 体は台の後ろ(台の端から 0.5〜1.0m)を左右に動く。最高の速さまで滑らかに近づき、ラリーの合間は中央へ戻る |
| 振り | 打つ 0.25 秒前にラケットの手を後ろへ引き、打つ時刻に打点を通り、振り抜く。届く範囲より外の球は空振りになる |
| 返球 | 狙う着地点を決め(強さで散らし方が変わる)、そこへ落ちる速さを同じ計算で数回試して求める。ネットの上 0.03m を越えなければ少し上げる |
| ミス | 返せる球でも確率でミスする。ミスは空振り・ネット・オーバーを 2:1:1 で選ぶ |
| サーブ | ボールの手で 0.3m 投げ上げて打ち、プレイヤーのコートへ直接入れる |
| 反応 | 決着時に体を小さく跳ねさせる(得点)・うつむかせる(失点)。表情の差し替えは `docs/art-direction.md` |

強さ3段階(1つの設定アセットにまとめ、Inspector で調整する。数値は目安):

| 値 | やさしい | ふつう | つよい |
| --- | --- | --- | --- |
| 反応までの時間 | 0.30 秒 | 0.18 秒 | 0.10 秒 |
| 左右に動く速さ | 1.5 m/秒 | 2.5 m/秒 | 3.5 m/秒 |
| 体の中心から届く横の範囲 | 0.6m | 0.75m | 0.9m |
| 返球の速さ | 5〜7 m/秒 | 7〜10 m/秒 | 9〜13 m/秒 |
| 着地点のばらつき(半径) | 0.30m | 0.18m | 0.10m |
| 狙う場所 | 台の中央付近 | 左右に散らす | 隅と、プレイヤーのいない側 |
| 返せる球でのミスの確率 | 20% | 8% | 3% |
| 速い球(10m/秒以上)でのミスの上乗せ | +25% | +12% | +5% |
| サーブの速さ | 4〜5 m/秒 | 5〜7 m/秒 | 7〜9 m/秒 |

#### CPU の体(仮人形と girl.vrm)

| 項目 | 内容 |
| --- | --- |
| 仮人形(標準) | プリミティブで組む。頭(球)、胴(カプセル)、腕のない丸い手2つ(プレイヤーの頭と手の表示と同じ考え方)。身長 1.5m 前後。ラケットとボウリングの球は手に付ける。腕がないので関節の計算は要らない。見た目は `docs/art-direction.md` |
| 差し替えの仕組み | 体は「CPU の体」の部品で切り替える。動かす側は体の位置・向き・ラケットの手の目標・反対の手の目標・反応の種類だけを渡し、仮人形と VRM のどちらでも同じに動く |
| girl.vrm | ユーザー本人が作った VRM 1.0(vrgame2 の `games/sky-runner/assets/girl.vrm`)。作者本人のみ利用可・改変禁止のため、ファイルもモデルの見た目も変えない(帽子などを体に付けない。強さの見分けはモデルの外の名札などで出す) |
| VRM の動かし方 | 外部の人型アニメーションは調達しない。エディタ処理で作る「構え」の1コマだけのクリップ(腕を下ろし膝を軽く曲げる。T ポーズを避けるため)と、IK(ラケットの手を目標へ、反対の手は体の横かサーブの投げ上げ)、体の左右移動と向きで動かす。髪などの揺れは UniVRM の機能に任せる |
| UniVRM が無いとき | UniVRM に依存するコードは別のアセンブリに分け、パッケージがあるときだけコンパイルされるようにする。無いときは仮人形で全機能が動く |
| ユーザーのエディタ作業 | 1. Package Manager で UniVRM(VRM10)を入れる 2. girl.vrm を `Assets/ThirdParty/UserModels/girl/` に置く 3. メニュー「VRGame3 > CPU の体を VRM にする」を実行する(本体が手順を渡す) |
| Git | girl.vrm と取り込みで生まれるファイルはリポジトリに入れない(`Assets/ThirdParty/UserModels/` を .gitignore に足す)。他の PC では仮人形で動く |
| 確かめること | URP で MToon の表示が崩れない(崩れたらユーザーに相談し、モデルのファイルは触らない)。表示中も 60fps を保つ |

#### ボウリングの CPU 対戦

| 項目 | 内容 |
| --- | --- |
| 進め方 | 交互にフレーム。プレイヤーが1フレーム投げ終わると、隣のレーン(X +1.8)で CPU が1フレーム投げる。CPU の番の間はプレイヤーのボール置き場のボールを掴めない |
| CPU の投げ方 | ボールは物理で実際に転がす(ピンも既存の物理で倒す)。CPU は手にボールを持って後ろへ引き、前へ振り、振り子の一番下で放す(スクリプトの動き)。1投目はポケット(1番と3番の間)、2投目は残ったピンの真ん中を狙い、強さに応じて狙いと速さを散らす |
| 強さ3段階の目安 | 速さ やさしい 6 / ふつう 7 / つよい 8 m/秒。狙いのばらつき(ピンの位置で左右) 0.15 / 0.08 / 0.04m。平均スコアの目安 90 / 140 / 190(Inspector の値で合わせる) |
| 表示 | 大型スコア板の2段目に CPU のスコア(見た目は `docs/art-direction.md`)。CPU のストライク等の演出は小さく、プレイヤーの演出と重ねない |
| 結果 | 勝敗と両者のスコア。腕前ポイントとベストは自分のスコアだけで1人のときと同じに扱う |
| 試験用 | CPU だけで続けて10ゲーム投げ、平均を出す切り替えを Inspector に用意する(強さの合わせ込み用。普段はオフ) |
| 休憩案内の区切り | CPU のフレームが終わってプレイヤーの番になったとき |

#### モードの選び方

ハブの看板の「あそぶ」から会場へ入り、各種目の「はじめに」パネルでモードを選ぶ。ハブの看板は増やさない。

| 種目 | 選べるモード |
| --- | --- |
| ボウリング | ひとりで / CPU と(やさしい・ふつう・つよい)/ こうたいで(2〜4人)/ チャレンジ |
| アーチェリー | ひとりで / こうたいで(2〜4人)/ チャレンジ |
| 卓球 | CPU と(やさしい・ふつう・つよい)/ チャレンジ |

- 最後に選んだモードと強さを覚えておき、次に開いたときに選んだ状態で出す(保存はしない。アプリを閉じるまで)
- 結果の「もういちど」は同じモード・同じ強さ・同じ人数で始める
- 卓球のハブの看板と入口は、ボウリング・アーチェリーと並べて置く(ハブの組み立て処理に足す)

#### 交代プレイ

| 項目 | 内容 |
| --- | --- |
| 人数 | 2〜4人。「はじめに」パネルで選ぶ |
| 名前 | 「プレイヤー1」〜「プレイヤー4」で固定し、文字入力はしない。人ごとに色の印を付ける(色は `docs/art-direction.md`) |
| 種目 | ボウリング(10フレーム)とアーチェリー(18本)。卓球は入れない |
| 順番 | 1人が1ゲームを通して遊び、終わったら次の人へヘッドセットを渡す(フレームごとに渡すと付け外しが多すぎるため) |
| 交代のとき | 「プレイヤー2 の番です。ヘッドセットとコントローラーを渡してください」を出し、「はじめる」で次の人の「はじめに」パネルへ進む。パネルで身長・利き手をその人に合わせ、周囲確認とストラップの案内を毎回出す |
| 身長・利き手 | その人の番の間だけ使い、保存しない。全員が終わると保存した設定に戻す |
| 1人終わったとき | その人のスコアを数秒出してから交代の案内へ進む |
| 全員終わったとき | 順位表(順位・プレイヤー・スコア。同点は同じ順位)。下に「もういちど(同じ人数)」「ハブへ」 |
| 記録 | ベスト・遊んだ回数・腕前ポイントは保存しない(保存は1人分のため。持ち主の記録はひとりで遊んだものだけ) |
| 途中でやめる | メニューの「ハブへもどる」で全員分を取りやめる(確認は M2 と同じ) |

#### チャレンジ

種目ごとに3つ、合わせて9つ。課題は設定アセットに並べ、数値は Inspector で調整する。

| 種目 | 課題 | クリアの条件 |
| --- | --- | --- |
| ボウリング | ぴったり7本 | 1投でちょうど7本倒す。5投以内(毎投ピンを並べ直す) |
| ボウリング | スペアをねらえ | 1フレームでストライクかスペアを取る。3フレーム以内 |
| ボウリング | はしっこの1本 | 10番ピン(利き手が左なら7番)1本だけ立った状態から倒す。3投以内 |
| アーチェリー | ねらいを保て | 10m で3本続けて8点以上。6本以内 |
| アーチェリー | とおくの的 | 30m で6本中3本を的に当てる |
| アーチェリー | 6本で45点 | 20m で6本の合計 45点以上 |
| 卓球 | ラリー10回 | やさしい CPU(ミスしない)とラリーを10往復続ける。3回まで |
| 卓球 | ねらい打ち | CPU の球出しを返し、相手コートの隅の円(直径 0.5m、左右どちらでも)に入れる。10球中3球 |
| 卓球 | 5点マッチ | ふつうの CPU に5点先取で勝つ(デュースなし) |

- 選び方:「はじめに」パネルの「チャレンジ」から3つの課題の一覧を出し、1つ選ぶ。一覧には課題名・条件・クリア済みの印
- 遊んでいる間:スコア板の場所に課題名と残りの回数(投・本・球)を出す
- 終わり方:クリアしたら「クリア!」、できなければ「ざんねん」。下に「もういちど」「ほかのチャレンジ」「ハブへ」
- 保存:クリアした課題の ID の一覧だけを保存する(保存形式の版を上げる)。ベスト・回数・腕前ポイントは動かさない
- 表示:ハブの看板に「チャレンジ 2/3」のようにクリア数を出す
- 休憩案内の区切り:1回の試み(1投・1本・1球)が終わったとき

### M4 磨き込み

M4 は「完成の定義」(この項の最後)を満たすための段階である。新しい遊びは足さず、初めての人が迷わないこと・見た目と音の仕上げ・遊び込みで出た不具合の始末に絞る。

M2・M3 は実機の試遊がまだなので、M4 の実装はその試遊と並行してよい。ただし試遊で出た指摘の修正は、下の実装順のどの作業よりも先に行う。

作業は下の実装順で進め、各段階の終わりに実機で動きを確かめてから次へ進む。シーンへの組み込みはこれまでどおりエディタのメニュー(「VRGame3 > ○○を作る」)で行い、ユーザーのエディタ作業は手順にして渡す。

| 順 | 作業 | 終わったときに確かめること | 完成の定義に要るか |
| --- | --- | --- | --- |
| 1 | 不具合・不満の一覧を作る(下の「不具合・不満の一覧」)。M2・M3 のゲートの試遊を行い(ユーザー)、出た指摘を一覧に入れる | 一覧に M2・M3 の試遊の結果が入っている | 要る |
| 2 | 保存の版 3(下の「設定と保存の追加」)と、共通の設定パネルの2つの面(「からだ・いどう」「けしき・おと」) | 版 2 の保存ファイルから読んでも記録とクリアが残る。新しい項目が再起動後も残る | 要る |
| 3 | 音量(全体・BGM と環境音)と、シーン切り替えのときに環境音と BGM を下げる処理 | 0 で無音になり、10 で今と同じ音量。フェード中に環境音が下がって戻る | 要る(音量は不満の一覧に出やすいため) |
| 4 | 時間帯3パターン(リアルタイム)。設定の値、時間帯の設定アセット3つ、各シーンで当てる部品、組み立てメニュー | ハブと3会場のそれぞれで朝・昼・夕焼けに切り替わり、ピン・的・卓球の球がどれでも見える | 要る |
| 5 | チュートリアル(ハブの最初の案内、3種目の手順の板、コントローラーのボタンの光) | 保存ファイルを消すと最初だけ出て、操作をすると次の手順へ進み、2回目からは出ない | 要る |

#### 音量

| 項目 | 内容 |

| 全体 | すべての音にかける(AudioListener の音量)。0 は無音 |

| 作り | AudioMixer は使わない(エディタのメニューで組み立てられないため)。音源に「音の種類」(BGM・環境音 / 効果音)の部品を付け、種類ごとの倍率をかける。シーンの組み立てメニューで既存の音源に付ける |
| フェード | シーン切り替えで暗くし始めると、BGM・環境音の倍率を 0.3 秒で 0 へ下げ、明るくするときに 0.3 秒で戻す(`docs/art-direction.md` 7.4) |

#### チュートリアル

ねらいは「初めての人が、作者に聞かずに最初の1投・1本・1球までたどり着ける」ことに限る。文は短く、操作の絵(Vive ワンドの絵で押すボタンに色を付けたもの)と一緒に出す。

| 場所 | 出すとき | 中身 | 消えるとき |
| --- | --- | --- | --- |
| ハブ(はじめての案内) | ハブに初めて入ったとき(てびきを見た印に hub がない) | 頭の正面 1.0m のパネル(メニューと同じ出し方)。「ようこそ」と4行の操作の絵:トリガー=えらぶ・つかむ / パッドのまんなかを押す=いどう(はなした所へ)/ パッドの左右を押す=むきをかえる / メニューボタン=メニュー。連続移動がオンなら2行目は「パッドにふれた方へ いどう」 | 「わかった」を押す |
| ハブ(看板の案内) | はじめての案内を閉じたあと、まだどの種目にも入っていない間 | 3枚の看板の「あそぶ」の上に「ゆびさして トリガー」の小さな札と下向きの矢印 | 種目に1つ入ったら hub の印を付けて消す |
| ボウリング | 「はじめる」を押したあと(印に bowling がない) | 手順の板(ボール置き場の上、目の高さより少し下)。1「ボールに手を近づけて、トリガーを引いたまま もつ」→ 2「うでを ふって、レーンの方で トリガーを はなす」→ 3「たおしたピンの数がスコアになる。10フレーム あそぼう」 | 1は掴んだら、2は投げたら次へ。3は1投目の結果が出てから 4秒で消し、印を付ける |
| アーチェリー | 同上(archery) | 手順の板(「はじめに」パネルの位置)。1「弓は自動で もちます。反対の手を 弦のまんなかに近づけて トリガー」→ 2「トリガーを引いたまま うしろへ引いて、はなすと 矢がとぶ」→ 3「点線は 矢のとぶ向き。的のまんなかを ねらおう」 | 1はつがえたら、2は放ったら次へ。3は1本目が刺さるか消えてから 4秒で消し、印を付ける |
| 卓球 | 同上(tabletennis) | 今のサーブの案内の板を手順の板として使う。1「ボールの手の トリガーで ボールが出る。はなすと上に投げる」→ 2「ラケットを ふって ボールに当てる。ボタンは いらない」→ 3「相手のコートに 入れよう。おちた球は ひろわなくてよい」 | 1は投げ上げたら、2は打ったら次へ。3は最初の1点の決着から 4秒で消し、印を付ける |
| ボタンの光 | 手順の板が出ている間 | その手順で使う手のコントローラーの、使うボタン(トリガー・パッド)をゆっくり光らせる(1秒に1回まで)。文字は手元に出さない(0.5m より近くに文字を出さないため) | 手順が進んだら止める |

- 交代プレイでは、てびきの印に関係なく全員に毎回出す(交代で遊ぶのは初めての人が多いため)。印は付けない
- チャレンジでも印がなければ出す。CPU 対戦も同じ
- 手順の途中でハブへ戻ったときは印を付けない(次にまた最初から出す)
- 「はじめに」パネルの周囲確認・ストラップの案内は今のまま毎回出す(てびきとは別)
- 消えるまでの秒数、板の位置、光らせる速さは Inspector で調整する
- 入れないもの:音声の読み上げ、動く手本(お手本のアニメーション)、練習モード、操作の絵を動かすこと

ゲート(完成の定義の各項を、実機で次のように確かめる):

- 初めての人:VR に慣れていない人を含む2人以上に、保存ファイルを消した状態でヘッドセットを渡す。作者はストラップの装着を手伝い、危ないときの声かけだけをして、操作は説明しない。ハブの案内から看板で種目を選び、3種目を1ゲームずつ遊ぶ(卓球は やさしい)。合格:全員が3種目とも最初の1投・1本・1球を作者に聞かずに出せて、作者が操作を口で教えた回数が 0 回
- 2回目:同じ保存ファイルで続けて遊ぶと、ハブの案内と3種目の手順の板が出ない。「あそびかたを さいしょから」を押すとまた出る
- fps:朝・昼・夕焼けのそれぞれで、ハブ → ボウリング(CPU 対戦、ストライクの紙吹雪を含む)→ ハブ → アーチェリー(X の紙吹雪を含む)→ ハブ → 卓球(1ゲーム)→ ハブを通し、SteamVR のフレームタイミングで 16.7ms を超える場面が無い。UniVRM を入れている場合は girl.vrm の CPU で行う
- 時間帯:ハブで変えるとフェードを挟んで切り替わり、位置と向きが動かない。会場では変えられない。夕焼けでもピン・的のリング・卓球の球・パネルの文字が読める・見える(試遊者に聞く)。再起動しても選んだ時間帯で始まる。焼き込みが無い状態で確かめる
- 音量:全体 0 で何も鳴らず、BGM・環境音 0 で効果音だけ鳴る。再起動後も残る
- 保存:版 2 の保存ファイル(M3 までに遊んだもの)を残したまま起動し、ベスト・ポイント・ランク・チャレンジのクリアが残っている
- 一覧:`docs/playtest-notes.md` の全行の判断が「直す(直した)」か「直さない」で、「未定」と未修正の「直す」が無い
- 酔い・事故:上の試遊と、M2・M3 のゲートの試遊で、酔い・事故の指摘や発生が無い(時間帯を変えるときのフェードを含む)
- 見た目のご褒美(順7 を入れた場合):試験用の切り替えで全解放し、4つの品の4種類がそれぞれの場所に出る。切り替えを戻すと、ランクとクリアの数どおりの解放に戻る

完成の定義(すべて満たしたら完成とする):

- 初めての人が説明なしで、ハブから3種目を選んで遊べる
- 3種目・3時間帯のどれでも 60fps を保つ
- 自分で遊び込んで出た不具合・不満の一覧が、直したか「直さない」と決めたものだけになっている
- 試遊で酔い・事故の指摘がない

最初の作業はM0のフォルダ作成とサンプルの整理で、これはリポジトリ vrgame3 にそのまま積み上げていける。

## リスクと対策

最大のリスクは「種目を広げすぎて1つも完成しない」ことで、対策は1種目ずつ遊べる状態まで仕上げてから次へ進むことに尽きる。

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 種目を広げすぎる | 未完成のまま止まる | M1でボウリングを完成させるまで他種目に着手しない |
| 投げる感触が気持ちよくない | 遊びの核が成立しない | M1で手触りの調整に最も時間を使い、他人にも試してもらう |
| 8KXの高解像度で処理落ち | 酔い・不快感 | 毎週実機で 60fps を保てているか確認し、M0 以降の全ゲートに fps の条件を入れる。ローポリと共有パレットで負荷を抑える |
| 卓球の当たり判定 | ボールのすり抜け | 卓球は3種目目に回し、それまでに物理の知見をためる |
| M1 の試遊を後回しにした | 投げ心地や安全の問題が遅れて見つかり、ボウリングの手直しが M2 に食い込む | 試遊は M2 の実装順4(アーチェリーのルール)が終わった時点で一度行ってよい。ボウリングの指摘は Inspector の値で直せるものを先に直す |
| 弓の操作が分かりにくい | 初めての人が矢を放てない | つがえる距離・ねらいの補助を Inspector で調整できるようにし、試遊で最初の1本を放つまでの様子を見る |
| 卓球で球が台に入らない | 初めての人が1球も返せず楽しくない | 入りやすさの補助(既定オン)と、やさしい CPU の遅い球。順2 の時点で作者以外にも一度打ってもらう |
| 卓球で体を大きく動かす | 台にもたれる・床に手を伸ばす事故 | 周囲確認に「台はほんものではない」を足し、ボールは拾わせない。動ける範囲は自分の側の台の後ろだけ |
| CPU の作り込みが膨らむ | M3 が終わらない | 動きはスクリプトだけ(アニメーション素材を調達しない)。体は仮人形で先に完成させ、VRM は最後に差し替える |
| girl.vrm の扱い | 利用条件(作者本人のみ・改変禁止)に反する | リポジトリに入れず、モデルのファイルと見た目を変えない。UniVRM が無くても動く作りにする |
| M4 の磨き込みが終わらない | 完成しないまま手直しが続く | M4 は完成の定義に要る作業(順1〜6・8)を先に行い、見た目のご褒美(順7)・正式モデル・焼き込みは削れる作業にする。直すか直さないかは不具合・不満の一覧で1件ずつ決める |
| 夕焼けで暗く見にくい | ピン・的・卓球の球を見失う | 太陽は背中側か横に置き、時間帯の設定アセットの強さと環境光を Inspector で上げられるようにする。M4 のゲートで試遊者に見え方を聞く |
| 初めての人が操作で止まる | 完成の定義を満たせない | てびきは操作をしたら進む手順の板とボタンの光にし、交代プレイでは毎回出す。ゲートで作者が口で教えた回数を数える |
| 参考作品に似すぎる | 権利面の問題 | 個人で遊ぶ範囲なので影響は小さい。名称・キャラはオリジナルにしておく |

決めておきたいこと:

- [x] 対応デバイス:PC VR(Pimax 8KX / Pimaxシリーズ)
- [x] 公開:しない(個人で遊ぶ)
- [x] 3Dモデル:無料アセットを優先し、足りない物だけ自作
- [x] 使用するUnityのバージョン:6000.6.7f1(Unity 6)
- [x] 使うコントローラー:HTC Vive コントローラー
- [x] 掴む操作:トリガー(グリップではない)
- [x] 移動:テレポート+スナップターンが標準。連続移動は設定で切り替えるオプション(M2)
- [x] 期間:締め切りは設けず、ゲートを越えたら次へ進む
- [x] フレームレート:目標は 60fps
- [x] メニューボタン:M2 で全種目共通の「メニューを開く」に割り当てる。グリップは空けたまま
- [x] ハブと会場の行き来:シーンの切り替え+短いフェード(M2)
- [ ] 8KX のリフレッシュレートを 60Hz に設定できるか、実機で確認する
- [ ] タイトル名:M4 の初めての人の試遊までに候補から選び、ハブのはじめての案内の「ようこそ」に入れる(ユーザー判断。決まらなければ「ようこそ」だけにする)
- [ ] 4種目目以降:M3 の完成後に決める
- [x] 卓球のラケット:「はじめる」で利き手に付く(トリガー不要)。回転は M3 では入れない
- [x] 交代プレイ:2〜4人、1人1ゲームずつ、名前は「プレイヤー1〜4」、記録は保存しない
- [ ] UniVRM を入れて CPU を girl.vrm にするか(ユーザー判断。入れなければ仮人形のまま)
- [x] 時間帯:設定パネルで選び(ハブでだけ変えられる)、保存する。リアルタイムで切り替え、焼き込みは任意の後作業(M4)
- [x] 見た目のご褒美:ボールの柄・弓の色・ラケットの色・手袋の色を各4種類。帽子は入れない(M4)
- [x] 音量の設定:M4 で全体と BGM・環境音の2つを入れる
- [ ] オンライン対戦:将来検討のまま残す
- [ ] Git LFS:モデルやテクスチャで容量が増えてきたら導入する
