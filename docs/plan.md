# VRスポーツリゾート 企画書(vrgame3)

2026-10-15 時点

## 企画概要

南国の島リゾートを舞台に、手や体を実際に動かして遊ぶ「体感スポーツ集」をVRで作る。最初はボウリング1種目を完成させ、種目を1つずつ足していく。

| 項目 | 内容 |
| --- | --- |
| タイトル案(仮) | 未定(候補は下記) |
| ジャンル | VRスポーツ・ミニゲーム集 |
| 一言で言うと | 島のリゾートで、気軽に何度でも遊べるスポーツをVRで「本当に体を動かして」楽しむ |
| 1プレイ時間 | 1種目 3〜10分 |
| 体験の核 | 投げる・打つ・引くが自分の手の動きそのままに反映される気持ちよさ |

参考作品(Switch Sports / Wii Sports Resort 系)から借りるのは「誰でもすぐ遊べる操作」「短時間で終わる種目」「リゾートの明るい雰囲気」の3点に限る。キャラクター・名称・デザインは完全オリジナルにする。

差別化はVRならではの3点に置く。

- 手の位置と向きが1対1で反映されるため、フォームの上達がそのまま上手さになる
- 島の景色に囲まれる没入感(海、ヤシの木、夕焼けの時間帯変化)
- 種目間を島の中で歩いて移動する「ハブ空間」で、ゲーム集でも一つの場所にいる感覚を出す

### タイトル候補

| 候補 | 意味・由来 | 印象 |
| --- | --- | --- |
| ソラシマ・スポーツリゾート | 空に浮かぶ島(空島)のリゾート | 舞台がそのまま伝わる |
| アイランド・アクティブ | 島で体を動かす | 短く覚えやすい |
| ココナッツ・リーグ | 南国の果物とリーグ戦 | かわいく親しみやすい |
| サンセット・スポーツ | 夕焼けの島で遊ぶ | 雰囲気重視、落ち着いた印象 |
| ハレバレ・アイランド | 晴れ晴れとした島 | 明るく、日本語の響きが楽しい |
| ナミノリ・スポーツ | 海辺で波に乗るような爽快さ | 海の印象が強い |

「スポーツリゾート」は参考作品の名前に近いが、個人で遊ぶ範囲なら問題はない。

## ターゲットとプラットフォーム

対象は PC VR の Pimax 8KX(および他のPimaxシリーズ)で、自分で遊ぶための個人制作とする。ストア公開はしないので、審査や他機種への対応は考えなくてよい。

| 項目 | 方針 |
| --- | --- |
| 想定プレイヤー | 自分(家族や友人が試すこともある) |
| 対応デバイス | Pimax 8KX / Pimaxシリーズ(SteamVR経由) |
| 実行環境 | Windows PC(自宅PCは RTX 4070 Ti) |
| プレイ姿勢 | 立ってその場で遊ぶ。座りプレイも可能な種目を用意 |
| 必要スペース | 2m × 2m 程度、ベースステーションの検知範囲内 |
| 入力 | SteamVR対応コントローラー(種類は要確認) |
| 目標フレームレート | ヘッドセットのリフレッシュレートに合わせる。8KXは解像度が非常に高いため、描画負荷を抑えることを最優先にする |

## 種目ラインナップ

最初に作るのはボウリング、次にアーチェリー、卓球の順とする。「その場から動かない」「物理が単純」な種目ほど、個人開発でも完成度を上げやすく、VR酔いも起きにくい。

| 優先 | 種目 | VRとの相性 | プレイヤー移動 | 物理の難しさ | 一言メモ |
| --- | --- | --- | --- | --- | --- |
| 1 | ボウリング | 高 | なし | 低 | 投げる動作が直感的。MVPに最適 |
| 2 | アーチェリー | 高 | なし | 低 | 弦を引く手応えがVR向き。的当てで得点が明快 |
| 3 | 卓球 | 非常に高 | なし | 高 | 一番VRらしいが、高速ボールの当たり判定が難所 |
| 4 | パターゴルフ | 高 | 少し(ワープ) | 中 | 座ってもできる。コース作りが楽しい |
| 5 | フリスビー | 中 | なし | 中 | 投げて犬がキャッチ。島の雰囲気づくりに合う |
| 6 | 剣のチャンバラ | 中 | なし | 中 | 対CPU戦。手応え(当たったときの反発)の表現が課題 |
| 7 | テニス | 中 | 自動移動 | 高 | 自分で走れないため自動移動が必要。後回し |
| 8 | カヌー | 低 | 常に移動 | 中 | 景色は良いがVR酔いしやすい。オプション扱い |

種目数は3つそろった時点で「ゲーム集」として成立させ、4つ目以降は反応を見て決める。

## コアゲームプレイと操作設計

全種目で「グリップボタンで掴む、離して投げる/放つ」を共通操作にし、説明なしで遊べるようにする。投げる速さと向きは、手を離した瞬間のコントローラーの速度から計算する。

### ボウリング(MVP)

1. ボール置き場でグリップを押してボールを掴む
2. レーンに向かって腕を振り、グリップを離して投げる
3. 離した瞬間の手の速度でボールの速さ、手首のひねりで回転(カーブ)が決まる
4. 10フレームでスコアを競う。ストライク・スペアの演出で気持ちよさを出す

調整ポイントは次の3つ。

- 投げる力の補正:実際の腕振りは小さいので、速度に倍率をかけて「強く投げた感」を出す
- 床への投げつけ防止:手が床より下に行ってもボールは床の上から出る
- 投げ損ね救済:ファウルラインより手前に落ちたら自動で転がす

### アーチェリー

片手で弓を持ち、もう片方の手で弦を掴んで引き、離して矢を放つ。引いた距離で矢の速さが決まり、重力で山なりに飛ぶ。弦を引いている間はコントローラーを細かく振動させて手応えを出す。

### 卓球

ラケットは手に持ったまま固定し、ボールとの当たり判定はラケットの速度と向きで反射を計算する。物理エンジン任せにすると高速ボールがすり抜けるため、専用の衝突計算(連続衝突判定)を自作する前提で、最も工数を見ておく。

### コントローラー

操作はコントローラーに統一し、ハンドトラッキングは使わない。Valve Index コントローラーなら指の開閉も取れるので、ボウリングやフリスビーの「握る/離す」をより自然にできる。

## ゲームモードと成長要素

初期は1人用とCPU対戦だけにし、オンライン対戦は種目がそろってから検討する。ネットワーク対戦は工数が大きく、1種目目の完成を遅らせるためである。

| モード | 内容 | 時期 |
| --- | --- | --- |
| フリープレイ | 好きな種目を1人で遊ぶ | MVP |
| チャレンジ | 種目ごとの課題(例:ピンを指定本数だけ倒す) | MVP後 |
| CPU対戦 | 強さ3段階のCPUと対戦 | 2種目目以降 |
| 交代プレイ | 1台のヘッドセットを回して家族・友人と得点を競う | 2種目目以降 |
| オンライン対戦 | 離れた相手とリアルタイム対戦 | 将来検討 |

成長要素は「腕前ポイント」1本にまとめる。勝敗とスコアでポイントが上下し、種目ごとのランク(ブロンズ〜プラチナ)で上達が見える形にする。報酬は見た目のみ(ボールの柄、弓の色、アバターの帽子など)とし、強さには影響させない。

## 世界観・アート・サウンド

アートは「明るいローポリ+柔らかい陰影」のスタイライズド路線にする。リアル寄りは8KXの高解像度で描画が重くなり、個人の制作量でも破綻しやすい。ローポリなら無料のアセット(CC0素材)と組み合わせても見た目の統一感を出しやすい。

- 舞台:空に浮かぶ小さな南国の島。中央の広場(ハブ)から各種目の会場へ歩いて行ける
- 会場:海辺のボウリング小屋、森の中のアーチェリー場、ヤシの木陰の卓球台
- 時間帯:朝・昼・夕焼けの3パターン。夕焼けは焼き込みライティング(ライトマップ)で軽く見せる
- アバター:頭と手だけの簡易表示から始める。全身アバターは腕の動きが不自然になりやすく後回し
- 観客・CPU:丸みのあるデフォルメ人形風。表情はテクスチャの差し替えで表現

3Dモデルの方針は次のとおり。

- 色はテクスチャ1枚のカラーパレット(グラデーション画像)を全モデルで共有し、描画負荷を下げつつ色味をそろえる
- 手に持つ物(ボール、弓、ラケット)だけは目の前で見るので、ポリゴン数と質感に予算を多く割く
- 遠景(海、空、島の外周)はスカイボックスと板ポリで済ませる

### 無料3Dモデルの調達先

3Dモデルは無料素材を優先し、足りない物だけ自作する。ローポリで統一された無料パックが多いので、アートの方針とも合う。ライセンスは目安なので、使う前に各サイトで確認する。

| 入手先 | 主な内容 | ライセンス(目安) | このゲームでの使い道 |
| --- | --- | --- | --- |
| Kenney(kenney.nl) | ローポリの小物・建物・スポーツ用品 | CC0 | ボール、ピン、的、小屋 |
| Quaternius(quaternius.com) | ローポリの自然・キャラクター | CC0 | ヤシの木、岩、CPUキャラ |
| Poly Haven(polyhaven.com) | 空のHDRI、テクスチャ | CC0 | 空と海、地面の質感 |
| Poly Pizza(poly.pizza) | ローポリモデルの検索サイト | CC0 / CC-BY 混在 | 足りない小物の補充 |
| Unity Asset Store の無料アセット | 環境一式、エフェクト | Asset Store の標準ライセンス | 島の地形、水面、パーティクル |
| Sketchfab | 多様なモデル | モデルごとに異なる | 目立たせたい1点物 |

サウンドは波の音と鳥の環境音を常時流し、ストライクや的の中心に当たったときの効果音を大きめに作って「気持ちよさ」を強調する。

## 快適性と安全設計

VR酔いの最大の原因は「自分が動いていないのに視界が動く」ことなので、カメラを勝手に動かす演出は一切入れない。種目の多くを「その場から動かない」ものにしたのもこのためである。

- 移動:ハブ内の移動はテレポート(指した場所に瞬間移動)を基本にし、スティック移動はオプション
- 向きの変更:スナップターン(一定角度ずつ回る)を標準にする
- 演出:ストライク時などもカメラは揺らさず、周りのエフェクトで盛り上げる
- 腕振り:強く振る種目では、プレイ開始前に「周りに人や物がないか確認」の表示を出す
- 手放し防止:最初にストラップを手首に付ける案内を表示する(コントローラーが飛ぶ事故対策)
- 休憩:20分ごとに軽い休憩の案内を出す(オフ可能)
- 身長差:身長と利き手を最初に設定し、ボウリングのレーンや卓球台の高さを合わせる

## 技術構成

Unity 6 LTS + OpenXR + XR Interaction Toolkit の標準構成で作る。OpenXR にしておけば、Pimax(SteamVR経由)でもコントローラーの種類の違いを吸収しやすい。

| 領域 | 採用技術 | 理由 |
| --- | --- | --- |
| エンジン | Unity 6 LTS | 情報が多く、PC VR向けの実績が豊富 |
| XR基盤 | OpenXR(SteamVR ランタイム) | Pimaxと各種コントローラーに対応できる |
| 操作 | XR Interaction Toolkit | 掴む・投げる・テレポートが標準部品で揃う |
| 描画 | URP(ユニバーサルレンダーパイプライン) | 8KXの高解像度でもフレームレートを保ちやすい |
| 物理 | Unity標準物理 + 卓球のみ自作の衝突計算 | 高速なボールのすり抜け対策 |
| 保存 | 端末内のJSONファイル | スコア・ランク・設定を保存 |
| オンライン | 未定(将来、Netcode for GameObjects などを検討) | MVPでは使わない |

リポジトリ(shuji30/vrgame3)のフォルダは種目ごとに分け、共通部品と混ぜないようにする。

```
Assets/
  _Project/
    Common/       … 掴む・投げる処理、設定、スコア保存、効果音管理
    Hub/          … 島の広場、種目選択
    Sports/
      Bowling/    … シーン、スクリプト、モデル
      Archery/
      TableTennis/
    Art/          … 共有パレット、共通マテリアル
  ThirdParty/     … 外部アセット
```

モデルやテクスチャが増えて容量が大きくなってきたら、Git LFS を導入する。

## 開発ロードマップ

M1でボウリングを「人に遊んでもらえる」状態にすることが最初のゴールで、各段階の終わりのゲートを越えるまで次の種目には進まない。期間は作業ペースが見えてから入れる。

1. **M0 準備**
    - Unity 6 LTS・OpenXR・XR Interaction Toolkit を入れ、Pimax実機で動かす
    - 全種目で使う「掴む・投げる」の共通部品を作る
    - ゲート:実機で掴んで投げた物が自然に飛ぶ
2. **M1 ボウリング完成(MVP)**
    - 1レーン・10フレーム・スコア表示・ストライク演出
    - 投げ心地の調整に一番時間を使う
    - ゲート:他の人に遊んでもらい「もう1回」と言われる
3. **M2 島のハブとアーチェリー**
    - 島の広場から種目を選べるようにする
    - アーチェリーを追加し、スコア保存とランクを入れる
    - ゲート:2種目を通して遊んでも72fps以上を保つ
4. **M3 卓球とCPU対戦**
    - 卓球の専用当たり判定と、強さ3段階のCPU
    - 3種目そろって「ゲーム集」として成立
    - ゲート:試遊で酔いや事故の指摘がない
5. **M4 磨き込み**
    - 見た目・音・チュートリアルを仕上げる
    - 自分で遊び込み、気になる点を直していく

最初の作業はM0の「実機で掴んで投げる」の確認で、これはリポジトリ vrgame3 にそのまま積み上げていける。

## リスクと対策

最大のリスクは「種目を広げすぎて1つも完成しない」ことで、対策は1種目ずつ遊べる状態まで仕上げてから次へ進むことに尽きる。

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 種目を広げすぎる | 未完成のまま止まる | M1でボウリングを完成させるまで他種目に着手しない |
| 投げる感触が気持ちよくない | 遊びの核が成立しない | M1で手触りの調整に最も時間を使い、他人にも試してもらう |
| 8KXの高解像度で処理落ち | 酔い・不快感 | 毎週実機で fps を確認。ローポリと共有パレットで負荷を抑える |
| 卓球の当たり判定 | ボールのすり抜け | 卓球は3種目目に回し、それまでに物理の知見をためる |
| 参考作品に似すぎる | 権利面の問題 | 個人で遊ぶ範囲なので影響は小さい。名称・キャラはオリジナルにしておく |
